# 页面与交互规范：整改目标

2026-11-16修订，适用于纯在线产品。本规范延续统一卡片和属性筛选，补充账号与云端任务衔接；本轮视觉与任务证据见[交付记录](../deploy/DELIVERY_V1.11.1_2026-11-16.md)。

## 信息先后

| 页面 | 直接看见 | 进一步了解 | 核对依据 |
| --- | --- | --- | --- |
| 导师卡 | 姓名、学校/院系、职称、博/硕导资格、方向摘要、邮箱、有效招募标签 | 现有导师详情的完整方向/简介/招募 | 简短来源与日期；详情中逐字段来源 |
| 导师对比 | 列头身份与联系动作，方向、资格、职称、邮箱及官方资料 | 后续行的其他已公开属性；双方都缺少的可选属性不占整行 | 逐字段官方出处、来源抓取日期；不重复列头已有身份 |
| 活动卡 | 主办方、活动类型、对象/限制、状态、关键日期、具名官方公告 | 完整材料、申请步骤、研究方向及联系人角色 | 公告与附件原句、核验日期；技术哈希下沉 |
| 学校要求 | 当前目标、申请条件、材料、时间及关键适用限制 | 完整学校/院系/专业规则与提交阶段 | 原文定位与附件；缺口和过期状态不可隐藏 |
| 申请工作台 | 当前项目、进行中的任务和下一步 | 材料、联系历史与阶段记录 | 关联政策/活动快照与私人操作时间 |

摘要用于做决定，不等同于把原文截短。影响准入的本校、专业、专项、费用和对象限制不得只在长文最后出现。不能放满“未知”后把真正可做的操作挤到屏幕之外。

## 导师筛选

常用条件直接可见：姓名、研究关键词、导师招生资格；学校多选可展开，职称与相关院系在更多筛选。已选学校与条件随时可清除；手机不要求横向拖动寻找条件。

删除目标学位和旧高级匹配规则，禁止只是把旧控件藏起来。筛选是属性匹配，不是“优先排序”。缺邮箱默认不显示；显式放宽时说明是资料缺口，不能写成老师没有联系方式。研究词的“任一命中”规则以一句话说明。

申请年度/学位/渠道继续属于学校与正式项目页，不作为发现页普通筛选，也不因旧URL或私人偏好静默生效。

## 导师卡片尺寸契约

- 同一断点下，本批4张基础卡等宽等高，误差≤1 CSS px；高度由本批内容决定，不能只让同一行等高，也不设置制造大块空白的固定总高度。
- 固定信息顺序和摘要行数预算：姓名最多2行，学校院系最多2行，方向最多3行；职称、资格、邮箱、招募标签与操作各有稳定位置。最终行高与总高度先以真实样本试排，不重新设一个过大的固定高度。
- 来源日期明确对象：邮箱出处仅显示邮箱采集时间，退回档案出处时标为资料采集记录；某个字段新近更新不能替代其他字段的采集日期。缺少日期或链接时各显示一次清晰提示。
- 长姓名、长邮箱和长方向有可访问的完整文本：邮箱可换行且链接可操作，完整资料通过现有详情页查看。不能只靠鼠标tooltip，不能截断到无法识别联系人。
- 资料短时也保持统一结构，但不堆叠多个空字段占位。默认有邮箱；方向未知只用一条简短说明，减少无意义大块留白。
- 主操作和次操作底部对齐；卡片不再通过就地展开大量证据改变列表基础尺寸。原有完整来源移至现有详情访问路径，不丢内容。
- 桌面/手机可采用不同的卡片高度；在各自断点内一致。200%缩放时优先保证文字与操作不被裁切，单独验收。

## 字体与控件

沿用共享 `site/ui.css` 作为单一入口，模板仅负责需要的布局。正文15px、辅助13px、控件14px；页面标题28px（手机24px）、区块20px、卡片17px；系统无衬线字体，正文行高1.65–1.7。

内容上限1240px，两侧24px（手机16px）；卡片10px圆角、白底细边框，内距20px（手机16px）。桌面控件至少40px高、手机44px；勾选框保留自身尺寸。深青绿用于主操作，中性灰用于辅助，警示色只标需要关注的真实状态。

一个区域只有一个主要操作。相同动作同名同样式；官方公告、报名入口、申请表不能全部叫“查看详情”。同URL重复入口只显示一次，角色不同的联系方式明确标注。

## 导航、空态与状态

按现有任务分组，维护工具和旧看板退出普通学生主要路径，历史记录仍可访问。不增加新的主模块。匿名浏览保持可用；私人操作引导注册或登录，并在完成后返回原导师、活动或项目。禁止转到安装、下载、电脑目录或本机服务。新账号空态明确给出建立申请的下一步，不要求先导入备份。

申请、材料和沟通在同一账号及项目上下文中衔接。提交中、已保存、失败与会话失效分别表达；失败不得清空输入或伪装已保存，退出后清除上一账号的私人视图。上传采用文件选择器，成功后显示文件和关联结果；下载失败可理解。保存草稿、确认实际发送、登记回复分别使用对应动作，不把保存记录写成已向学校提交。

无结果时说明当前条件、资料缺口及可继续的具体操作，不猜“没有导师/不招生”。加载失败保留已显示内容与已选状态；条件改变与已应用状态区别清楚，旧请求不能覆盖新结果。

原文锚点能展开并定位对应内容；键盘焦点可见。表格在自身容器滚动，页面不能横向溢出。已应用条件和返回位置需要程序保证，不能依赖偶然的bfcache。未保存表单的现状主要是允许取消离开，不保证刷新恢复，文案及验收按实际实现说明。

## 验收方式

先验证[用况](USE_CASES.md)，再做视觉与技术检查。固定混排6类真实导师样本，测卡片宽高及动作基线，检查完整文本去向；活动使用既有18条内容归类样本，验证主办方与来源一眼可辨，样本数量不是当前可报名数量。账号及申请流程必须在HTTPS页面上实际点击，不以直接调用API代替用户流程。

1440/390主要任务、320/768边界、200%缩放和键盘检查都记录截图及失败项。测试不得再以“自然高度成功”作为通过条件。静态截图、无JS错误、无溢出分别只说明对应检查结果，不能替代任务完成或用户认可。

## 首访与来源状态

加载中不先展示“0条”；在线目录读取超过8秒给出可恢复的降级状态，静态副本不得继续显示已确认报名。研究方向与联系人摘要放在活动主操作附近，完整条件、材料与来源可展开；自动证据核验日期与人工核对日期分别标注。学校条件按原文句号/分号分条，不能删去限制、例外、否定或改写时间。
