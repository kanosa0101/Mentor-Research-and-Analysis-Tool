# v0.12 项目近期行动摘要

项目卡片原先按保存顺序展示前三条项目日期。用户可能先看到已结束的报名轮次，而真正需要处理的提醒藏在提醒分区。本次把卡片摘要改为一条未完成提醒和一条后续安排，完整记录仍在原分区保留。

## 展示与交互

- 未完成提醒只从该项目的 `project_id` 精确匹配记录中选择，排除已完成记录，按计划日取最早一条；同时显示未完成总数。
- 提醒状态分为“逾期未完成”“今天”“待办”。关联导师的提醒注明导师，项目级提醒注明“项目事项”。不受当前导师或提醒分区的“仅显示未完成”选项影响。
- “查看此项目提醒”入口从折叠的目标与要求提升到卡片摘要。没有提醒时入口仍显示，便于用户继续新增；沿用 v0.11 的项目范围、返回上下文与未保存输入确认逻辑。
- 后续安排按原有 `AdmissionsRules.eventState` 排除已经过去的项目日期。官方事件快照和个人计划明确区分，报名/材料截止、考试/考核、资格相关时间、个人计划保留各自类型。
- 原日期字符串及精度完整显示。官方快照附当前来源核对状态和“申请前核对原文”，不会由日期未过推断报名开放。
- 全部日期已过或未登记日期时，显示“尚未登记后续安排；不表示没有申请截止时间”。历史日期仍可在“目标与要求”展开查看。
- 归档项目显示“归档记录”和保留的未完成提醒，未自动取消提醒，也不把归档解释为正在申请。

## 时间规则

1. 提醒日期与“今天”使用北京时间，摘要与提醒列表共用状态计算；今天不使用逾期样式。
2. 仅有日期的项目安排在北京时间当天仍视为未过去；带时区的精确时间按实际时刻判断，同日已经过去的精确时间不进入后续安排。
3. 不同日期先按北京时间日排序。最早一天内如果全部为精确时间，再按实际时刻排序。
4. 如果最早一天含未注明时刻的日期，保留这一天的登记顺序。另有同日记录时明确提示“先后未确定”，不假定未注明时刻的日期发生在午夜；完整安排可展开查看。
5. 排序使用筛选出的新数组，不改变保存顺序、日期值、来源、私人索引或 API 结构。
