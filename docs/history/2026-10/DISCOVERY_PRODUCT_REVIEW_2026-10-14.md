# 用户条件、信息获取与展示方案（0.3）

## 用户真正需要完成的事

用户需要把“心仪导师”缩小到一个可解释、可联系、可持续推进的名单：研究兴趣接近，申请年度与渠道适用，导师确实有对应资格和招生机会，自己的报名条件满足，且有可靠联系方式。搜索只是第一步；找到人后仍需核对简章、整理材料、写有依据的联系信、记录回复和下一步。

这些判断不能合成一个“匹配率”。用户更需要知道哪些条件已满足、哪些明确不满足、哪些还不知道，以及如何补齐未知。本版把必须条件与偏好分开，并保留待核实候选，避免官网信息缺失造成错误排除。

本轮使用以上官方页面核对产品设计。开源联系/CRM实现及许可边界沿用 `OPEN_SOURCE_IMPLEMENTATION_REVIEW_2026-10-14.md` 和联系闭环0.2；本版没有复制第三方源码。产品方案的关键是采用分面搜索与逐项证据，而不是引入未经核验的评分。

## 条件来自哪里，怎么让用户看懂

| 用户关心的条件 | 如何获取 | 本版展示与判断 | 未知时下一步 |
| --- | --- | --- | --- |
| 申请什么年度、硕士还是博士、哪个渠道 | 用户直接选择，不能从导师资料猜测 | 顶部目标摘要；条件与核验均绑定目标；进入联系和项目管理时带过去 | 留空可发现导师，人工确认招生机会前必须明确 |
| 想研究什么 | 用户输入中英文关键词；检索官网研究方向与简介文字 | 任一关键词命中；显示命中字段、片段、来源和抓取日期。短语逐字段匹配，不跨字段拼接；英文避免 `ml` 命中 `HTML` | 文本未命中只表示文字未命中，去完整资料确认；同义词需要用户补充 |
| 能接受哪些学校 | 用户多选；学校身份来自既有官网库 | 明确院校范围，空为不限；不把院校排名作为隐含筛选条件 | 扩大院校范围或增加新的官方院系配置 |
| 有没有对应学位导师资格 | 官网导师资格字段与逐字段出处 | 明确对应“博/硕”才命中；博导不自动推断硕导；否定或缺失记待核实 | 打开字段出处、院系导师名录核实 |
| 有没有公开联系方式 | 官网邮箱字段与出处 | 公开邮箱存在可命中，但显示仍需使用前核对；没有邮箱记待核实 | 查主页/院系联系渠道，不猜邮箱 |
| 本年度该渠道是否接收申请 | 当年官方简章、院系/导师官方通知；用户核对原文后记录 | 独立招生机会状态；来源、原文、核验日期可见；不把资格等同名额，不自动使用标题年份 | “查招生通知”定位所选院系；未接入明确显示未接入；继续查官网 |
| 我是否满足申请资格 | 用户按当年原文核对成绩/排名/语言/专业等要求 | 与招生机会分开，可分别确认/不满足/未知；只存本地私有核验记录 | 当前需人工核对；没有做自动成绩或语言规则判定 |
| 地区、实际校区、经费、指导方式 | 未来需官方地址/当年项目/导师说明及用户直接询问；带适用范围和日期 | 本版明确未统一核验，暂不提供虚假的自动过滤 | 先选学校，联系时明确询问；不能从所属学校猜实际招生校区 |

本次现有公开库核对：5649名导师、36校、42院系；研究方向字段1859人（32.9%），导师资格字段3025人（53.6%），邮箱4550人（80.5%）。方向字段缺失仍可检索简介。官网抓取日期只是数据年龄，并不保证官网内容仍有效。年度机会和个人资格本版没有全库自动覆盖。

## 系统如何保证信息可用

公开信息继续采用名单驱动爬虫、逐字段 provenance、手工来源保护和变更/issues记录。发现页只读取已有静态公开索引；输入主题时按需加载简介全文，来源索引独立加载。不改写导师公开资料，也没有新增自动推断字段。

筛选条件与人工核验放在独立 `data/discovery.yaml`，不混入公开生成物或原工作流。核验键固定为导师+年度+学位+渠道；更改其中一项不会复用其他上下文结论。超过30天或日期异常，规则按未知处理，历史原文仍可查看。这是复核提醒，不是对任何招生信息有效期的保证。

确认/不满足结论必须有 HTTP(S) 来源、原文和显式人工确认。系统验证结构与引用，无法自动证明填写的网站是官方或原文支持该结论；界面明确要求人工核对。当前本地工具按一个使用者保存个人资格，不提供多账号共享判定。

本机同源 API 负责原子写入和校验；读取不创建文件。条件备份与工作流备份分开，恢复前保留旧原始副本。静态打开仍能筛选，私人保存与核验按钮禁用。

## UI 与后续推进顺序

八类页面共用纸白背景、森林绿主色、统一导航、标题、表单和卡片基线。发现页采用左侧条件、右侧证据卡片，手机折成单列；详细来源表仅在卡片内横向滚动，页面本身不溢出。保留全量表和导师对比，方便用户进一步比较。旧看板明确标成历史入口。

发现→完整资料/通知→准备联系→项目材料→草稿导出→人工发送确认→回复/任务的闭环保持可用。无法唯一且明确匹配项目类型时，用户选择目标，避免把“统考（非推免）”等旧自由文本误接到推免项目。

下一版优先做以下范围，每步要求来源和独立验收：

1. 将当年招生规则整理为项目级结构化条件，逐条保留原文、适用年份/学位/渠道与人工复核；先针对用户选中的少量院系，不宣称覆盖全库。
2. 增加用户自填的专业、成绩/排名和语言资料，与简章逐条对照；缺少口径或信息时仍未知，不能自动宣称符合资格。
3. 建立经核验的地点/校区、导师身份与近年论文绑定，再增加地区偏好和研究证据；先保证实体正确，再谈排序。
4. 在真实使用者选导师与联系过程中记录搜索耗时、未知补齐比例、误排除案例和下一步完成率，评估界面是否减少实际操作。

当前验收是本地功能与浏览器测试，尚不是实际申请成功、招生信息全覆盖或用户体验研究结论。
