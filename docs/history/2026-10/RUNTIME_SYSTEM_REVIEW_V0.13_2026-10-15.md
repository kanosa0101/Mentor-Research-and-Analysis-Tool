# v0.13 运行与数据保护审计

## 检查范围与修复

基于 v0.12，检查新用户冷启动、服务入口、本机服务安全边界、正式 Python/Node 测试、采集预检，以及公开载荷和真实私人文件的保护基线。本报告不替代本轮最终集成与页面验收。

发现启动输出仍指向旧 `board.html`，README 顶部首先出现大量历史版本记录。现已在 README 顶部补充依赖、构建、启动和五步使用流程，保留全部历史记录。服务启动输出改为“找导师”“我的申请与联系”“项目、材料与提醒”三个当前入口。

真实占用端口冷启动原来抛出 traceback。现在对地址占用（含 Windows 10048）及 Windows 10013 给出“已被占用或系统不允许绑定”的中文提示和 `--port` 操作建议，退出码 1；其他启动异常仍抛出以便诊断。Windows 10013 在真实端口占用测试中实际出现，不能仅按 10048 处理，也不能将权限问题断言为端口占用。绑定仍固定 `127.0.0.1`，参数默认值及私人存储规则不变。

## 可用性验收清单与边界

1. 按 README 从根目录安装、构建并启动，三个当前入口可达；端口不可用时可按提示换端口。
2. 找导师 → 学校与招生要求 → 结构化项目 → 材料 → 提醒 → 联系与记录流程，需要由页面验收复核上下文和保存行为。
3. 创建、编辑、备份和恢复应只在临时私人文件验证；正常 GET 不迁移或写真实文件。服务已检查本机 Host/Origin/Referer/JSON 类型，并在工作流写入前校验，使用原子替换；恢复保留旧原始字节。
4. 官方政策、材料条件和导师名额仍须按范围核验。五组 11 项采集缺口是明确数据限制，不应将服务可启动解释为全校全院系数据完整。
5. 本地服务没有后台通知、邮件自动发送及真实申请提交能力。`.eml` 的实际客户端发送和申请结果不属于本轮运行测试。

未发现需要阻断本地受限版本交付的新增运行问题。未增加公网部署、账户权限、多用户并发写入或外部通知能力，现有本机模式必须继续按文档使用。
