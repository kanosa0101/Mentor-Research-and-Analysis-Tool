# 使用手册 · v1.5.0

本工具服务于 CS 学生寻找导师和整理研究生申请。优先按自己的路径、届别和专业核对原文；资料完整度、导师资格、当前名额和本人申请资格不能互相代替。

## 1. 选择公开站或本机版

公开站：[申请导航](https://8.213.137.82:8443/start.html)。可以浏览资料、收藏公开条目和登记浏览器待办；不接收私人申请文件、邮件草稿或正式项目。

本机版需要 Python 3.12+。解压到独立目录，在目录中执行：

```powershell
python -m pip install -r requirements.txt
python scripts/serve.py
```

打开 `http://127.0.0.1:8000/start.html`，或在安装依赖后双击 `启动应用.cmd`。终端须保持运行，Ctrl+C 停止。端口占用时增加 `--port 8001` 并相应改用 8001。已有生成页面，无需首次采集、重建或下载 Playwright 浏览器。

## 2. 从自己的申请路径出发

申请导航分两条路径：2027 年入学统考、2028 届毕业保研准备。年份可按实际目标调整，不能把活动标题的年份直接当作毕业届别。

选择学校和研究兴趣后，下方入口随选择更新；点击“保存为关注目标”才写入浏览器。学校可以搜索、多选和清空。未选学校时可跨校探索。保存关注目标只是方便继续查找，不创建本机正式申请项目，也不会向学校提交。

统考路径用于核对目标专业、考试及当前进程。2027 入学推免属于上一轮历史参考，不能当作 2028 届保研要求；当前统考通知也可能是确认、考试或结果阶段，并非仍在接受报名。

## 3. 找导师与核对招生范围

“找导师”支持姓名、研究关键词、学校多选和相关院系筛选。多个研究词按任一命中查找，姓名与研究条件取交集。修改条件后点击“查看候选”。默认优先信息较完整的导师，同等完整度随机排列、会话内稳定。

先看研究方向、简介、公开联系方式和来源时间，再打开官网核对。院系方向用于导航，不自动认证跨专业资格；未知条件不等于不符合。加入对比可并排查看，名单跨院系时不按同名自动合并。

在“学校与要求”核对学校、院系、入学年度、学位、渠道、普通/专项及正式专业；校级规则与院系、专业补充需一起看。展开原文和定位，分别查看摘要核验时间与来源检查时间。缺少文件、只有专业目录或来源失败时，保留缺口，不能理解为没有要求。

“招生通知”可按届别、渠道及阶段筛选；通用校章可从“查看同年通用政策”补查。发布时间、入学年、活动年和事项截止分别判断。“覆盖与缺口”展示已整理的 15 个单位及待补内容，不代表全部学校已覆盖。

## 4. 浏览器收藏、待办与备份

导师、招生通知或机会卡片上的“收藏到此浏览器”，保存在当前站点的浏览器中。回申请导航“我的浏览器收藏与待办”管理关注目标、收藏和待办，也可从收藏增加跟进事项。

待办的计划日期仅用于页面排序和标记，不是官方截止，不会发送后台个人提醒。删除浏览器收藏不会删除本机正式项目。

点击“导出浏览器备份”下载 JSON。导入时先校验并预览数量，点击“确认合并新增条目”后才保存；已有记录保持不变。这与本机工作台的替换式恢复不同。

记录按浏览器和站点隔离：HTTP 与 HTTPS、不同域名或端口、不同设备不共享。隐私模式、清除站点数据或换浏览器可能丢失记录。迁移前先导出，在目标站点导入；不要依赖账号云同步。

## 5. 创建正式项目并准备材料

正式项目需要本机服务。从政策页“创建申请目标”或机会页“加入我的申请”进入，核对项目名称与范围后明确保存。项目记录学校、院系、年度、学位、渠道、普通/专项、专业代码和名称；同一导师在不同年份或项目中分别推进。

先在“材料”登记本机文件并关联项目，再在准备清单为具体动作选择文件、登记状态和备注。按阶段和人工状态筛选仅改变视图，不表示所有事项都适用或已经齐备。

准备记录保留目标、来源与文件版本。文件修改、来源变化或目标切换后需重新核对。人工“已准备”“已登记提交”不是自动上传或学校收件确认；来源过期时可以保留个人准备事实，但不能借此确认新的报名条件。

活动保存为项目快照；后续公共资料更新会提示条件、材料或时间差异，不覆盖快照、个人进度和提醒。科研实践与正式招生分开；官方仅明确截止月份时不会补成月末某日。

## 6. 联系导师与个人提醒

导师卡片“准备联系”进入本机工作台，先选项目，保存选择理由和优先级。根据已核对的研究资料填写主题、正文、收件人及相关文件。程序不会根据未核实信息编造匹配依据。

保存草稿或导出 EML，在自己的邮件客户端检查正文、收件人和附件后发送；之后再登记实际已发、回复、约谈或补材料。沟通历史追加保存。

项目和导师均可添加多个个人提醒。保存官方日期不会自动建立提醒；个人计划与官方截止分开。未保存输入在切换时可取消离开。个人提醒与浏览器简易待办、公共更新通知属于不同功能。

## 7. 公共活动更新通知

在 HTTPS 公开站的保研机会页面选择学校、活动类型或关键词，主动订阅并授权浏览器通知。可以测试连接、退订；新发现未核验线索需另行选择，不当作已开放报名。

后台通知依赖服务器任务、浏览器、操作系统和推送服务，不保证即时送达。公共订阅不上传本机私人项目、材料或个人提醒。关闭后台运行、禁止系统通知可能影响到达，仍应回看站内更新和官方原文。

## 8. 更新公共资料，不覆盖自己的申请

在本机申请导航底部：

1. 先保存其他页面的编辑，点击“检查新版资料”。
2. 核对资料发布时间和要求的客户端版本。版本不一致时，先按下一节升级运行包。
3. 点击“更新公共资料”并明确确认，保持本机服务运行，等待页面显示结果；不要在此期间手工改公开数据或重复运行构建。
4. 成功后刷新导师、政策及通知页面。已保存项目快照仍保持原样，按差异提示自行核对。

下载归档、逐文件摘要、schema、路径白名单和客户端版本均会检查。新资料先在暂存目录构建页面；校验或构建失败不替换原资料。替换异常会尝试恢复本次备份。更新只涉及允许的公开资料和生成页面，不改私人工作流、材料原件、浏览器记录或程序代码。

旧公开文件保存在 `cache/public_updates/backup-<版本前16位>/`，安装记录在 `cache/public-data-installed.json`。保留错误提示和备份目录，不要为重试而删除备份。尚未发布资料版本、网络失败或 HTTPS 校验失败时继续使用旧资料，并查看其日期。

公开站已使用服务器发布的资料，无需在公开浏览器中执行文件更新。配置 `data/opportunity_feed.json` 的可信 HTTPS 站点同时用于公开资料服务；不要改成来源不明的下载地址。

## 9. 已有私人数据如何升级

运行包升级与公共资料更新是两件事。升级程序请按以下步骤操作：

1. 在旧版分别导出工作台备份、筛选核验备份，以及每个使用站点的浏览器备份。
2. 另存材料原件、学生画像、SOP、独立信件和整个旧私人数据目录；保留旧运行包及其备份。不要只备份生成网页。
3. 将新运行包解压到新目录，安装依赖并启动。停止旧服务或为新服务选择不同端口，确认访问的是正确实例。
4. 用新版本页面导入对应备份。工作台与筛选核验恢复会替换相应私人文件，并在替换前备份，不是合并；浏览器备份则确认后仅合并新增记录。
5. 核对项目、联系历史、材料路径、提醒和活动快照。材料原件不在工作台备份中；文件移动后应重新关联正确路径。
6. 核对无误前保留旧目录。需要回退时使用旧程序和与它兼容的旧备份，不假设旧版能读取新备份。

不要用旧 `data` 整目录覆盖新版 `data`，这样会把新版公开政策一起替换回旧资料。只迁移明确的私人文件，优先使用页面备份/恢复。

## 10. 故障与回滚

公共资料下载、校验或构建失败：先查看提示，检查网络和客户端版本；旧资料仍可使用，不能当作已更新。文件替换异常后，检查是否已恢复和本次备份是否存在。

需要人工回滚公开资料时，先停止本机服务与维护任务，另存当前完整目录，再依据本次备份恢复对应公开文件。备份只包含被替换路径，不应合并覆盖私人目录；若不能确认文件清单，使用保留的旧运行目录更稳妥。恢复后核对页面与政策时间，必要时请维护者处理安装记录。当前没有“一键回退版本”按钮。

浏览器数据丢失需要导入事先导出的浏览器备份；公共资料备份不能恢复它。本机材料原件丢失也不能从工作台索引恢复。

## 11. 维护者核验工作台

普通学生不需要运行此服务。维护者先取得队列，再启动：

```powershell
python scripts/review_opportunities.py sync
python scripts/serve_review.py
```

打开 `http://127.0.0.1:18769/review.html`。可筛选优先级、看原文和 PDF 页码、比较建议与已发布内容、明确采纳或保存草稿。核验发布须填写核验人、说明并确认，随后重新抓取官方 HTML/PDF；版本、页码、关键条件证据不匹配时拒绝发布。多窗口修改会提示重新打开最新草稿。

采纳和保存不发布，发布只写本机公开目录，不自动部署。该服务固定监听本机；公开站不开放核验页面和写接口。扫描件、证书失效、来源无法访问及范围不明仍需处理，不能通过填写“已核验”绕过。
