# 收尾优化前的产品审计

日期：2026-11-15；本地运行基线v1.9.0（aecb478e7）。**本轮是只读盘点和文档修订，未修改产品实现、迁移数据或重新部署。** 旧工程验收结果仍是历史事实，但用户已否定其整体体验。

## 1. 问题为何没有被上轮验收拦住

| 用户看到的问题 | 实际原因 | 本次修订 |
| --- | --- | --- |
| 保研机会混进个人实习招募 | 需求与模型把research_program当宽泛科研招募，缺主办层级约束；监测/AI发布门禁只重事实可验证，没有同等约束产品归类 | 内容门禁先区分院校活动、导师招募、招生通知、待核验，再决定展示与推送 |
| 来源看不清 | 主办方、发布平台、发现栏目、公告、附件、报名入口和联系人角色没有统一可读顺序；同域候选有时被当作完整来源链 | 卡面显示具名来源与状态，详情可逐字段回查；缺失链路明示 |
| 导师卡片大小不一 | v1.9规范主动选择自然高度，CSS使用align-items/start及align-self/start；测试还把自然高度当成功 | 改为同断点等宽等高、固定摘要预算与底部操作对齐；长内容进入现有详情 |
| 筛选选了却没有明显变化 | “目标学位”默认偏好；硬条件同时保留未知，使无邮箱/未知资格仍出现 | 以导师资格、职称等事实严格过滤，邮箱默认门槛独立；删除旧匹配模式 |
| 页面仍繁杂 | 关注目标、申请项目、联系人、私人核验、旧套磁等对象直接并列，压缩文字没有减少理解成本 | 页面围绕任务分工，低频维护和旧系统下沉；不要求用户掌握内部模型 |
| 验证很多但效果仍差 | 验证偏向DOM、无溢出、接口安全与状态保留，缺内容归类、筛选直觉、混排对齐和完整用户任务 | 需求→用况→样本验收→技术回归分层记录，不以测试数量宣称用户认可 |

上轮确实检查过截图，但“自然高度卡片”和“高级区保留匹配规则”的设计判断不符合当前用户要求；不能把问题归结为用户未理解设置。

## 2. 机会目录：18条不等于18条院校活动

审计覆盖全部18条及现有61个来源配置。17份原文快照与登记哈希吻合，高能所缺已核验正文。**本轮只对软件所、北师大和同济3个官方详情回查**；其余基于已登记证据及存档，没有全部重新核验，也没有据此重新发布。

| 整理去向 | 数量 | 说明 |
| --- | ---: | --- |
| 活动页 | 9 | 7条历史营/研修，2条当期机构项目；不代表2条当前正在报名 |
| 导师招募标签 | 6 | 复旦张帆、交大洪亮、科大胡奇强、西湖丁士超、北航解佳豪、人大董谨豪 |
| 招生通知/学校要求 | 1 | 同济正式2027入学推免预报名，保留历史轮次 |
| 待核验/待定 | 2 | 高能所缺可靠正文；北师大是学院实习管理/岗位征集，具体学生岗位与对象边界需核对 |

软件所科创计划由所研究生部统一组织，具有部门初选、系统立项与统一结题安排，符合院所级例外；不能因此把个人教师主页招募也归成院所项目。[软件所官方通知](https://www.iscas.ac.cn/yjsjy/zsxx/202610/t20261028_8299649.html)

北师大公告是学院统筹实习管理，导师征集与学生申请是不同阶段，不能把“全体本科生”直接解释为全国院校学生。[北师大官方通知](https://ai.bnu.edu.cn/ggjxz/tzgg/f7db49ad446c4a8ca26a34a80c4677e1.htm)

6条个人招募没有现成mentor_id。只有董谨豪存在同校同邮箱候选，但cs/info院系不一致；复旦张帆不能误绑库内中南或浙大的同名人。缺关联不能靠猜测补齐，迁移时必须保留原始记录与旧项目快照。

完整18条主办判断、官方链接、来源状态、附件、原文快照与局限见[逐条审核](audits/2026-11-15/opportunity-audit.md)和[JSON](audits/2026-11-15/opportunity-audit.json)。分类决定见[内容规则](CONTENT_RULES.md)。

## 3. 导师目录：有邮箱字段不等于有可用联系地址

按当前前后端一致的邮箱格式规则，逐条核对7173条导师记录与生成索引。统计是记录数，不是去重后的自然人数。

| 项目 | 数量 |
| --- | ---: |
| 全部导师记录 | 7173 |
| 邮箱非空 | 5668 |
| 邮箱格式有效且有HTTP(S)字段来源记录 | 5639 |
| 邮箱空缺 / 非空但格式异常 | 1505 / 29 |
| 有效邮箱集中明确博导 / 硕导 / 同时具备 | 1966 / 1373 / 287 |
| 有效邮箱集中资格未明确 / 职称缺失 | 2587 / 1202 |
| 有效邮箱集中缺明确研究方向 | 2969 |
| 职称非空原始表示 | 50种 |

5639条中5637条来源为院校或中科院域名采集，2条来自教师个人github.io主页；都有字段来源URL及获取时间。这里没有重新访问5639个来源，更没有发送邮件或验证送达。

29条异常邮箱分布为湖南大学26、吉林大学1、武汉大学2，常见问题是邮箱与电话粘连，应回查原文修复。按默认邮箱规则，哈工大和西工大当前名单会没有结果；空态需说明“本库暂缺可用邮箱”，不能说没有导师，也不能擅自取消用户的学校条件。

只读查询确认：当前degree=phd默认偏好可返回全部7173条；“邮箱必须符合”叠加keep_unknown=true也可返回全部7173条。问题来自规则语义，不能只删除下拉框外观。新口径需同时改公共查询、浏览器回退、计数、排序、分页及旧偏好读取。

另外，当前搜索状态保存了已应用条件，但未保证加载到第40位后的页数/滚动位置恢复；一次浏览器后退成功不能作为完整回访保障。

完整字段分布、来源域名、只读探针和用况建议见[导师审计](audits/2026-11-15/discovery-audit.md)及[统计JSON](audits/2026-11-15/discovery-field-inventory.json)。

## 4. 系统与文档整理结果

当前系统有四套合理隔离但对用户难懂的记录：公共资料、浏览器收藏、本机申请、维护核验；公开站、本机8000和维护台18769也是不同能力边界。本轮不引入云服务解决这些问题，先整理现有入口、命名和转接说明。

整改前，根目录PRODUCT_PLAN仍指向v0.20/阶段三，IMPLEMENTATION_PLAN仍是2026-10-13的旧工作清单。旧UI规范的“自然高度”与用户要求冲突，“刷新保留未保存输入”又超出现有beforeunload保护能力。旧文档原字节归档后，新的权威入口改为地图、需求、用况、内容规则、UI规则和四阶段实施计划。

详尽代码/API/数据/部署/测试地图见[系统盘点](audits/2026-11-15/system-map.md)。[运行架构](../ARCHITECTURE.md)、[交接](../HANDOVER.md)与[用户手册](../USER_GUIDE.md)继续描述v1.9现状，显式标注与整改目标的区别。
