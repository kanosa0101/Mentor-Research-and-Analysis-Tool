# v1.12.7 导师资料与联系准备优化计划

2026-11-23。以上线并复验的 v1.12.6 最终提交 `14d0c433889a74d0a3f0f710c42e5d76cd405ea8` 为基线。继续纯在线版，不增加学生业务模块。上一轮实际改变了线上资料、解析规则与页面，并完成发布验收，本轮从新的可复现缺口继续推进。

1. **确认缺口和来源。** 三名 Sol 子代理分别核对上海交大计算机学院、国科大自动化研究所、国科大计算技术研究所。先用每院不超过 12 份真实样本确认官方具名依据和解析边界，再扩大到现有档案。生产旧档原件、来源时间和 SHA 单独保存；目录差异只生成候选，不直接新增人员。
2. **修复持续采集。** 只调整三个院系的现有适配及必要配置。用正常字段补齐、资料轮转和质量恢复入口回放，验证人工与非目标字段保持、冲突保留、重复运行不新增或改写。独立主页须有具名官方链接并可读取，不把已有登记页再记为主页来增加完整率。
3. **简化实际联系流程。** v1.12.6 的手机实测显示，从导师对比进入时仅传入学校与院系，却出现招生适用性提示，具名卡片连续两行重复姓名。本轮只消除这两处显示冗余。真实申请条件、已保存目标和跨院系提示仍须可见，登录、返回搜索、建立项目及选择已有项目的上下文需要实测保持。
4. **集成、部署和验收。** 批次独审通过后，逐档核对生产前值并导入；完整回归、Linux CI、正常重建及真实公网流程通过后，绑定 GitHub 与部署版本。保留账号、材料、其他院系更新和回滚原件，分别报告实际字段增量与不能核验的缺口。

三个院系预研共 917 份已有档案，研究方向缺口分别为 147、147、112；这些是待核现状，不是本轮补齐结果。当前活动仍须满足院校主办、申请对象、明确届别与报名时间的独立发布条件。上轮已确认 AI 服务余额不足，本轮规则可核实的公开导师字段不调用付费 AI。

## 已确认的解析问题

- 计算所真实页面以 `yjfx` 变量渲染“研究方向”，旧适配误取导师类别中的招生学科。现有 171 份非空字段呈现三类学科名或其标签残留，不能当作已完整。逐档同时核对本人身份、旧字段来源、导师类别与实际方向，证据充分且非人工维护时才生成纠正候选；补空与纠错分别计数，由正常轮转持续处理。
- 自动化所和计算所的具名官网页明确链接到国科大托管本人主页，但两个官方域不属于同一 DNS 机构边界。仅为已证实的 IA / ICT → `people.ucas.ac.cn` 本人主页关系建立窄读取规则：先核各院模板中原本人页的明确链接，再核目标姓名、对应院所和个人栏，保留双端原件。邮箱、一般详情和政策采集的机构边界不随主页例外放宽。
- 联系页“仅导师所属院系”场景已在真实 HTTPS 账号测试中复现：本来没有申请条件，却显示招生范围说明。修复只改变显示；带有效申请条件、缺失或不一致院系、已保存完整目标的场景继续显示相应说明。
- 独审用自动化所真实原文复现普通轮转绕过邮箱归属检查的路径：如果某档邮箱留空而该地址已被另一档占用，旧路径仍会写入。该问题须在发布前修复，普通刷新、质量重试和 CLI 禁止绕过字段队列的本人身份及全库邮箱归属门禁；本批没有因此直接填入邮箱。
