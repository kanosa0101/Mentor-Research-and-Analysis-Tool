# 找导师：现状审计、用户用况与下一轮设计口径

审计日期：2026-11-15。范围：当前本地源码、7,173 份导师 YAML 与当前生成的公开索引；仅分析和只读探针，未修改产品、数据或部署。本报告服务于需求确认，不表示新设计已实施。

## 1. 结论与明确需求

用户最新要求应作为本轮约束：删除“目标学位”筛选，改为导师招生资格（博导／硕导）；现有“更多筛选”内容全部移出导师筛选，换成职称等导师自身属性；原则上不展示无邮箱导师；卡片尺寸应统一。

问题首先是筛选语义，随后才是样式。当前选“博士”只是资格偏好，返回候选总数不变；即使“邮箱”选“必须符合”，默认保留未知仍会展示无邮箱者。用户以为选定条件就缩小范围，实际却只改变排序。隐藏旧设置不能解决这个问题。

建议把“找导师”定义为：**从有公开有效邮箱的导师目录中，按研究兴趣、学校、明确导师资格和职称缩小候选，查看资料，对比后联系。** 申请年度、渠道、个人资格和当期名额属于具体申请目标核对，不再作为找导师的筛选项。

“有有效邮箱”这里只表示格式符合当前前后端规则并有公开来源记录，不表示邮箱仍在使用、可送达、本人回复或正在招生。

## 2. 项目地图与当前实际链路

| 位置 | 职责与此次调整的影响 |
| --- | --- |
| `site/templates/discovery.html.j2` | 筛选 DOM、卡片样式、项目核对表单。当前 `#candidate-list` 为双列网格、`align-items:start`，卡片 `align-self:start`，实际高度随内容变化。 |
| `site/discovery.js` | 读取/恢复条件、多校选择、公共 API 调用、本地回退、渲染、20→40 翻页、对比/联系、私人核对。当前 degree/year/route 与项目目标绑定，不能只删 DOM 而不拆状态。 |
| `site/discovery-core.js` | 浏览器匹配、邮箱格式、资格识别、完整度与随机排序；公共 API 失败、file 模式或私人核对时使用。 |
| `crawler/public_discovery.py` | `/api/mentor-candidates` 公开筛选、总数、排序及分页；`PARAMS` 目前不接受职称或独立导师资格参数。 |
| `crawler/public_catalog.py` | 读取生成索引并以路径、mtime_ns、大小、inode 做 LRU 缓存，最多 4 个文件版本；另提供按已选 ID 的对比数据和研究正文搜索。 |
| `crawler/discovery_util.py` | 私人偏好/备份的严格字段校验、旧核对记录；当前结构明确包含 year/degree/route/modes/keep_unknown，直接改字段会破坏旧备份。 |
| `scripts/build_site.py` | 从 YAML 构建 `discovery-data.js`、`search.js` 和页面；发现页内联轻量学校目录、规则、界面 JS 与样式，不内联全量导师索引。 |
| `scripts/serve.py` / `scripts/serve_public.py` | 本机/公开站共用同一候选函数；响应 JSON `no-store`。本机有私人服务边界，公开站不接收私人申请内容。 |

普通 HTTP/HTTPS 路径调用候选 API，每次最多 20 位；后台针对完整索引计算。存在项目范围或私人核对记录时，浏览器改为加载完整 `discovery-data.js`，研究搜索优先调用 `/api/mentor-search`，失败再加载 `search.js`。第一次公共分页失败后，该页面会保持本地回退路径。

默认排序：资料完整度高者优先，同层按 sessionStorage 中的种子稳定随机，不代表匹配分、导师实力或录取概率。有研究词、degree、year/route、某些 hard 条件或私人核对时，先按命中数/未知数排序，再按完整度。完整度由研究方向、有效邮箱、简介、HTTP(S) 资料链接四项组成。

公开候选 API 每次遍历并排序符合条件的结果，没有结果集缓存；只有 JSON 文件解析缓存。revision 来自 `discovery-data.js` 和 `search.js` 的文件时间/大小/inode。翻页发现 revision 改变会重置为首 20；请求序号防止旧结果覆盖新条件；下一批失败保留已有列表。当前机制要保留，新的职称与资格条件必须加入前后端相同筛选和 revision/版本兼容设计。

`saveView/restoreView` 保存同一 URL 对应的条件、姓名、院系分类，但不保存已加载页数和滚动位置。正常重新载入回到首 20，浏览器 bfcache 有时保留页面不代表程序保证恢复第 40 位。对比列表独立存于 localStorage，最多 5 位。

计数按导师记录 ID，不跨院系合并同名或同邮箱人员；不是唯一自然人数。统计依据：`crawler.public_discovery.valid_email`，与 `site/discovery-core.js` 当前正则一致。逐条核对生成索引和原始 YAML 的 email/title/supervisor，7,173 条均一致。

| --- | ---: |
| 导师记录 | 7,173 |
| email 非空 | 5,668 |
| 符合当前有效格式规则 | **5,639** |
| email 空缺 | 1,505 |
| email 非空但格式异常 | 29 |
| 有有效邮箱的学校 / 有导师记录的院系 | 37 / 52 |

29 个异常邮箱分布：湖南大学 26、吉林大学 1、武汉大学 2。常见实际错误为邮箱与电话粘连，例如域名后紧接电话号码；不能将这种字符串直接当作可联系地址，也不应在展示层凭猜测静默截掉尾部。

只有资格、职称不全，不应从默认可联系目录删除：否则将把资料覆盖缺口误作用户不感兴趣。用户主动选择资格或职称后，再按确证字段严格过滤。

哈尔滨工业大学、 西北工业大学当前名单没有通过格式校验的邮箱。中南大学自动化（114 条）、哈工大计算机（240 条）、西工大计算机（23 条）、上海交大 AI（1 条）这 4 个有名单单位会在默认“有公开邮箱”规则下变成 0 个可联系候选。页面必须明确“本库暂缺可用邮箱”，不能写成“没有导师”或悄悄取消学校过滤。仍保留院系官方名录入口、已有详情和历史收藏访问。

5,639 条中的 4,754 条资料 source_date 早于 2026-10-16；这是记录级来源日期，不是邮箱专门复核日期。全部具备 email provenance 不等于今天复核过，更不能用新 UI 版本日期替代来源日期。

补充字段级来源审计：5,639 条均具有 `provenance.email.source` 的 HTTP(S) 链接和 `fetched_at`，可追溯来源缺失 **0**。其中 5,637 条为院校或中科院域名采集记录（5,214 为 edu.cn/ac.cn，423 为 cas.cn）；另 2 条人工登记来源是教师个人 `zhangyuqun.github.io`、`mingkai-zheng.github.io` 页面，不能笼统称全部来自学校官方域名。此审计检查已存链接与字段来源结构，未重新在线核验这些网页，未发送邮件或验证可送达。

推荐首期类别：教授、副教授、助理教授、讲师、研究员、副研究员、助理研究员、其他已登记职称、未整理。明确修饰语可归到对应基础职称，卡片保留原称谓；工程/实验系列、职级信息、荣誉及行政值进入“其他已登记”并保留原文，不自行等同正教授。分类映射应有一张明确表和对应测试，后续再清理采集质量。

## 4. 只读 API 探针确认的问题

直接调用当前候选函数，不发写请求、不启动生产服务：

| 查询 | 返回总数 | 含义 |
| --- | ---: | --- |
| 默认 | 7,173 | 当前未排除无邮箱 |
| degree=phd 默认 | 7,173 | 博士选项是偏好，不是用户理解的筛选 |
| degree=phd，qualification=hard，保留未知 | 7,173 | 即使“必须符合”，未知仍留在结果 |
| email=hard，保留未知 | 7,173 | 无邮箱仍显示 |
| email=hard，keep_unknown=0 | 5,639 | 当前必须额外取消未知才得到有效邮箱集 |
| 北京理工 + 北京大学 | 306 | 多校并集运行正常 |
| 不存在的姓名 | 0 | 正常空结果 |

同种子重复请求首批完全相同，首 20 与下一批 20 无重复。单次本机样本默认约 341ms、热查询约 207–217ms、多校 17ms；只说明本次 Python 进程内探针，不是浏览器首屏速度或服务器 SLA。

不建议通过设置全部 `keep_unknown=false` 来实现新要求：旧机会与个人资格项仍是未知，会一并把有邮箱导师排光。应彻底分离“导师目录过滤”和“申请核对状态”。

## 5. 新筛选口径与状态边界

| 控件 | 建议语义 | 不能做的推断 |
| --- | --- | --- |
| 姓名 | 对姓名字段搜索；与其他维度取交集 | 不能把同名跨校导师合并 |
| 研究关键词 | 多词任一命中已知研究方向或公开简介；明确标记命中来自何处 | 未命中不代表真实研究不适合；简介命中不冒充方向标签 |
| 学校 | 搜索、多选，校内并集；已选 chips 保持可见 | 不因无邮箱或 0 结果自动清空用户选择 |
| 导师招生资格 | 不限／博导／硕导，选择后严格命中明确资格；双资格同时符合两种单选 | 博导不自动推出硕导；资格不等于当前名额 |
| 更多筛选：职称 | 标准类别多选，类内并集，与学校/资格取交集；保留原称谓 | 教授职称不自动推出博导，荣誉不等同职称 |
| 相关院系方向 | 如保留，置于更多筛选，按登记单位分类导航 | 不是导师研究关键词，也不是本科专业准入条件 |
| 公开邮箱 | 默认固化为有效邮箱要求；展示“有公开邮箱”口径提示，不再让用户理解 hard/soft | 不验证投递、不凭异常字符串猜邮箱 |

原则不展示无邮箱导师，建议首期不加默认可见的“包含无邮箱”开关：用户明确不希望这类条目占候选位。原始记录不删除；精准姓名搜索无可联系结果时说明缺邮箱，提供明确的“包含无邮箱记录”或全量目录/官方名录入口，由用户主动选择后查询；不悄悄往默认推荐列表补无邮箱卡，原收藏、已保存目标和对比历史不删除。

删除旧更多筛选中的入学年度、申请渠道、五种匹配模式与保留待核实设置。年度/渠道/项目学位及核对记录继续留在具体申请目标工作流，不能因前端删除控件而删除历史私人记录。

推荐新公共参数使用独立的 qualification（如 any/phd/master）和 titles；不能继续复用 degree 表示导师资格。跨页带入 `degree=master` 仍可能是真实项目学位，不应被新“博导/硕导”筛选反向改写；旧 URL、私人备份和 sessionStorage 需要显式兼容读取。旧 modes 不再暗中影响新目录结果，避免页面看不见的隐藏条件。

公共接口、浏览器离线/故障回退、默认列表、20→40 分页、总数、对比取数须遵循相同口径。筛选应发生在分页前，而非浏览器收到 20 位后删掉没邮箱者；否则会出现“总数 7,173，首屏只有 12 位”的错觉。资料完整度优先与会话稳定随机保留，但新筛选不靠“命中更多项”模糊排序代替。

## 6. 用户用况及验收条件

| 用况 | 用户希望 | 应有交互与可验证结果 |
| --- | --- | --- |
| 正常探索 | 不知道姓名，找研究相近且能联系的人 | 默认可联系列表；输入兴趣→查看候选，学校/资格/职称严格收窄；卡片能直接辨认研究、单位和邮箱。 |
| 明确博导/硕导 | 只看明确对应资格的人 | 博导不混入仅硕导或未知；硕导不混入仅博导；两种资格者均可命中；没有当前名额承诺。 |
| 多校 | 同时比较几所学校，不反复切换 | 学校可搜索/批选/逐个移除，收起后仍见已选；返回保持选择；结果为多校并集且分页稳定。 |
| 无结果 | 知道是条件太窄还是资料缺口 | 显示当前条件、逐项清除、官方入口；区别“有名单但缺有效邮箱”和“目录未覆盖”；精准姓名无结果可明确选择包含无邮箱记录/全量目录，不自动放宽资格或学校。 |
| 缺研究资料 | 知道是否值得进一步查 | 有邮箱可留默认目录；方向缺失用一行说明，官网简介明确单独标识；主动研究筛选无确切命中时不伪装匹配。 |
| 对比 | 记住跨页候选并排看 | 最多 5 位，20→40 后已选状态仍在，跨校原 ID 区分；已有无邮箱收藏可查看但说明联系缺口，不删除历史记录。 |
| 联系 | 快速复制邮箱、了解对方并准备有针对性的联系 | 卡片有效邮箱，资料页保留完整方向/官网；准备联系带导师 ID/单位，公开站明确本机准备边界，不冒称已发送。 |
| 查看资料后返回 | 继续刚才的位置 | 恢复姓名、关键词、多校、资格、职称、种子；建议进一步恢复已加载页数与所在导师锚点，版本变化则明确首批重置。 |
| 分页/服务故障 | 已找到的人不会消失 | 下一批失败保留现有内容；公共分页故障回退需保持新筛选一致；404 公共浏览与503本机不可用分别提示。 |
| 项目核对 | 找导师不破坏已有申请目标 | 目录资格只描述导师；原 degree/year/route 来自独立项目上下文；专项/专业目标不匹配时旧核对不借用。 |

## 7. 统一卡片尺寸，同时保留完整内容

已查看 v1.9 保存的 1440/390 截图。桌面卡片姓名和按钮位置随两行/三行方向及学校称谓变动，同一行底边不齐；移动首卡在约 783px 才开始，筛选占据大半首屏。现有自然高度策略与用户新要求冲突，需要明确替换。

推荐同一断点下折叠态等宽等高，用“固定摘要槽位 + 固定操作栏 + 现有详情页”建立整齐结构，而非给整卡很大的空白最小高度：

1. 姓名/导师资格一行；学校院系最多两行；职称一行。长名称可省略，但完整资料必须可键盘/触屏打开，不能只靠 hover 的 title 属性。
2. 研究方向统一三行摘要槽。无方向时在同样槽位显示一句缺口，或清晰标识的官网简介；不要使用简介填充为假的方向。正常摘要多余文本省略。
3. 联系邮箱统一一行或两行槽位（按统一断点制定），长邮箱省略但保留完整可复制值与 mailto；邮箱区域不因没有记录消失，因为候选集默认已有有效邮箱。
4. 固定位置的主要动作：查看资料、准备联系、加入对比；收藏为统一图标/次入口，不独占整段额外空白。
5. 完整研究内容、来源与申请依据走现有详情页及对应政策页，保证返回上下文。**不保留网格卡内展开长证据**，否则某一张会重新变高；本轮无需新建侧栏或弹层。
6. 每个断点所有卡片使用相同内容槽高度与按钮区域；不是只做同行 stretch，也不是 masonry。手机统一单列卡片结构，桌面两列。字号放大到 200% 时允许可读性覆盖等高目标，不能裁掉操作或必要文字。
