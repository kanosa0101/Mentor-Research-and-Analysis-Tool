# v1.12.3 内容维护与活动体验计划

本轮从已上线的 v1.12.2（最终提交 `b316dc7416c0fcb468c557295113d17580864e1b`）继续。目标仍是现有纯在线产品，不增加学生业务模块。上一轮已部署和完成公网验收，本轮先按真实运行记录确定问题，再集成上线。

1. **审核和服务恢复**。实际审核槽仍处理过期录取通知、历年分数线，新的政策在AI阶段遇到HTTP 402。一次计入日额度的最小请求已确认服务方余额不足，已向用户说明所需外部处理。历史分流必须有明确原文年份/窗口，不推断届别；服务阻断采用现有额度锁内的冷却和真实任务单次恢复尝试，防止无效重复调用或永久卡在人工状态。验证并发、配置更换、跨日额度、原证据保留，以及真实公告从准备到服务恢复的回放；模拟恢复不算真实核验发布。
2. **导师字段与来源**。Sol子代理处理北邮、厦大：初始生产库存分别为217档/0方向、51档/4邮箱/2方向。按官方具名来源准备逐字段补丁和正常维护入口，独立复核后以当前生产原始SHA导入。没有生产可续读取路径的来源单独注明，不能把开发浏览器抓取冒称服务器已可持续更新。对已确认的浙大两条表头误录核对零引用后下架，并修复日常构建、缺口队列和过期来源错误的自动收敛。
3. **活动阅读和保存**。活动卡片在手机上超过一屏，研究方向重复同一联系人；保存请求没有截止时间。保留原始申请条件、来源、明确届别与截止精度，压缩重复内容、让关键动作更早出现。已有筛选改为手机按需展开。保存超时明确结果未确认，保留输入、恢复操作、只允许用户显式重试，并使用服务端现有去重保证不新建第二个项目。验证手机/桌面、长条件、方向搜索和不确定保存后的恢复。
4. **集成与发布**。先冻结源代码和通过复核的资料，再完整回归、构建与GitHub CI；发布保留生产较新数据、账号和材料。公网复验可见字段、活动操作与无效记录下架，随后完成版本绑定、服务恢复和交付记录。用户只做最终验收，子任务由代理自行验收。

当期活动仍须按真正主办方及申请通道核对。校内推荐、科研研修和保研招生不是同一含义；主办方报到日期不能当报名截止，不同推荐校的截止不能合并为所有人可申请。招生条件、材料或报名系统证据不足时继续保留待核验，不能为增加条目而放宽发布门禁。
