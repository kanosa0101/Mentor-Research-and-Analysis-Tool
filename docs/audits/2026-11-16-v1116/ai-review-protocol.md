## 原因与改动

主代理对北京大学公开招生说明进行真实隔离核验时，完整输入为 5,789 字符，核验摘录共 5,263 字符；旧协议要求模型逐字回显摘录，90 秒总时限内未完成。这确认了该次超时，并暴露出可去除的响应冗余；是否改善真实供应商耗时须以改后服务调用验证，不能由本地 mock 宣称。

新协议继续发送完整 `official_text` 及每个字段原样的 `value`、`quote`。服务端在预留调用预算之前确认所有 quote 来自完整官方正文。模型只返回 `decision`、`issues` 和逐字段 `{field, consistent}`；`consistent` 必须是 JSON 布尔值。字段缺失、重复、未知、旧 quote 回显协议、字符串/数字布尔值、结论与字段判断或问题列表冲突均被拒绝。

仅全部字段为 true 且 issues 为空时可接受 consistent。服务端将原始本地 quote 附回审核记录，保存 `{field, consistent, quote}`；发布前仍按完整输入与原始摘录重新校验，不能用模型摘要替代原文。传输维持完整结束标记、90 秒总时限与原有大小界限，输出额度回到默认 6,000 tokens；删除按重复摘录字节数扩大至 24,000 的方案。

旧成功记录没有逐字段布尔值时不再符合新协议。自动审核版本或缓存复用条件应阻止旧协议结果被当作新核验复用；此次发布集成由主代理统一处理。
