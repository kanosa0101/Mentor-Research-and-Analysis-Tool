# 学校页关键加载请求收敛

## 实测诊断

依据部署后的 `cache/v1116/public-performance/result.json`，同会话切入学校页三轮就绪耗时为 3.291 / 5.897 / 4.368 秒。每轮均新增下载 7 个静态资源，没有共享资源缓存命中。完整政策数据 gzip 大小为 186,356 bytes，是最后完成的关键脚本，响应结束分别为导航后的 3.100 / 5.552 / 3.874 秒。

第二、三轮部分连接新建 TLS，约 0.92–1.18 秒；资源等待与连接合计约 0.36–1.18 秒。数据正文传输本身也消耗 0.992 / 3.630 / 2.006 秒，因此不能将全部延迟归因于握手或缓存。原始 CDP 记录显示远端为本机代理 `127.0.0.1:10808`，这是当前测试网络路径的结果，不代表公网直连性能。逐请求分段整理在 `cache/v1116/admissions-critical-path.json`。

## 最小改动

`scripts/build_site.py` 新增 `render_admissions_page`，复用既有 `entry_head` 与 `inline_scripts`。学校页的共用样式、账号/云端会话脚本及原有四个正文脚本随 HTML 返回，正文顺序仍为数据 → 规则 → 材料展示 → 页面逻辑，省去 7 个独立静态资源请求。模板无内联参数时保留原预览方式。

没有裁剪任何政策、原句、条件、材料、日期、来源及核验字段。当前完整 HTML 为 986,128 bytes，gzip 约 208,956 bytes；较大正文的传输耗时仍会存在，真实改善幅度由主代理窄补丁上线后复测。

## 验证边界

新增 `tests/test_admissions_entry_v1116.py` 使用真实 Chromium 验证只允许 HTML 与匿名账号 GET 时完整页面可用、政策数据与原始对象逐项相等、切换学校可用、规则及材料模块顺序正确；新输出目录使用新生成的数据，源码与已有页面字节不变；混合大小写脚本结束标签作为数据保存且不执行注入。未修改生产或创建账号。

学校页新回归及现有入口、界面、申请/导师构建回归共 16 项通过，29.03 秒，仅现有 pytest-asyncio 弃用警告。最终日志：`cache/v1116/admissions-inline-tests.log`。`git diff --check` 无空白错误。本地浏览器通过只证明功能与请求边界，不作为公网提速结论。

## 部署后复测

学校页窄补丁 `d2483261e024b5d19432e5a5cad3c3d415982d79` 已上线，7份补丁文件哈希核验通过。最终18次真实页面测量全部通过；学校页切入为2.836 / 1.932 / 3.041秒，中位数2.836秒，较补丁前同脚本三轮的4.368秒约低35.1%。学校页仅额外读取匿名账号状态，7个独立静态资源请求已消除。桌面1440px与手机390px目标页均保留学校/院系选择和63个官方来源链接，无脚本错误或横向溢出。

全部测速CDP连接仍指向当前客户端代理127.0.0.1:10808，不是公网直连基准；样本量小且网络波动，不能将全部差异归于代码。院校活动页切入中位数从2.305秒升至3.862秒，三轮均首次下载共享资源；学校页内联不再预热下一页缓存，以及网络波动均可能影响该结果。该页仍是最终序列中最慢的切换，未宣称所有页面提速。完整结果的统计与原始证据哈希见 `public-performance-summary.json`；原始记录保留在 `cache/v1116/public-performance-final/result.json`。
