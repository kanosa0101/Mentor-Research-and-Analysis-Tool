# 来源阅读与受管联系人规则

## 已复现问题

- v1.12.8 的详情来源表最小宽度为560px，在320/390屏幕里可用宽度分别只有254/324px。页面本身不溢出，但来源表必须横向滚动；宽屏遇到长值时日期也被拆行。
- 缺少来源时生成空链接，文字来源说明也被当作URL。缺日期显示空白，无法分辨是未记录还是渲染错误。
- 南京大学基于真实本人页和真实个人主页的受控负例中，仅把“个人主页”标签改成“实验室主页”，单位联系人钩子已拒绝，但通用字段流程仍采纳并请求该链接。
- 中国科大旧方向混入履历时，按缺字段补全的流程可以正确保留旧值，却错误地把新解析短值的原件记为旧值已核验。

## 本轮修复

1. 详情来源沿用共享界面的760px断点，窄屏按字段纵向排布，保留六项信息，桌面仍为同一语义表格。日期使用完整时间标签，长值换行；较大字号时元数据转为单列。原文按钮保持44px触控高度。来源为空时提示未记录，文字说明按文字展示。
2. 单位可配置 `homepage_hook_only: true`，个人主页仅接受已声明联系人钩子的候选，再由已有目标姓名核验后写入。通用研究方向和非受管邮箱流程不受影响；旧泛型主页队列在发出请求前过滤。默认未启用的单位保留原行为。
3. 中科大本人邮箱允许原登记 `http://cs.ustc.edu.cn/...` 的精确同路径HTTPS证据，限定 `ustc/cs` 和 `ustc_cs` 钩子，保留姓名、已登记邮箱及原件捕获检查。其他主机、院系、路径或捕获URL不等价。
4. 已存在方向须与本轮解析值相同、并匹配其登记来源且非人工值，才记录重新核验；解析值不同不覆写旧方向，也不把新原件绑定给旧值。实际历史污染修复由有明确正文边界的单位普通采集入口执行。
5. 详情上方的“字段来源最晚抓取”只取实际字段采集日期的最大值，没有字段日期时显示空缺标识。它不再借用整档最后抓取时间；邮箱和其他字段的单独日期仍保留。

## 当前验证证据

- 新界面回归在修改前复现5项失败：两种窄屏横向阅读、两种桌面日期拆行、缺失来源日期。修复后覆盖320/390/850/1440、长方向与URL、人工来源、空来源、键盘展开、既有申请项目及较大字号。
- 真实危辉资料以同一份数据渲染前后界面，四种宽度共24张截图，读取了手机与桌面成图。两种窄屏来源内容宽度降为实际容器宽度，桌面仍可完整展示日期与链接；Chromium无脚本错误，辅助功能树仍识别为表格。此项为隔离预览，公网验证在部署后另记。
- 界面专项覆盖七种宽度及较大字号；独立回放另验证真实与压力档、14个双倍字号场景及申请上下文操作。独审发现761px双倍字号时列头不换行会挤出右侧来源，去掉这项限制后真实模板复验通过。
- 上线前按实际构建详情复核，发现102份更新资料的最新字段日期被整档旧抓取时间替代。补充三项回归先复现错误，再验证混合新旧日期、全空日期和无字段记录；正式公网验收同时检查这项总标签。
- 独立共享规则回归19项通过，含未启用规则的原行为、真实钩子候选、身份不符、人工空字段、旧队列、HTTPS等价边界及方向证据一致性。此前既有联系人与两校上一版本钩子相关回归138项通过。

原始运行结果与截图位于 `cache/v1129/ui-evidence/`；独立内容审校与最终部署验收单独记录，以上不代替生产验证。
