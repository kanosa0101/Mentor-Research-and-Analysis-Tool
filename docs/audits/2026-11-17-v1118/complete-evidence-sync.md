# 完整证据发布后的日常同步收敛

部署前只读集成审查发现两处实际持续维护阻断：完整发布后的普通 `sync` 默认重新走普通 HTML/附件提取，组合 SHA 不再含已核验的媒体；缓存复用分支在缺少规则建议时也会重算并覆盖完整组合 SHA。结果是内容未变却无法正常续鲜，动态页面还可能进入“来源变化”。另发现 `_renew` 二次回源没有传证据目录，导致无法找到已核验媒体台账；该处由活动子任务修复。

本子任务对 `opportunity_review.py` 做最小修复：

- `fetch.evidence_mode` 和 `review.evidence_mode` 持久记录 `complete`，兼容已有完整文档缓存及旧自动核验发布记录。
- 普通同步和直接取证继续使用完整模式；失败保留该模式，不能在重试后悄悄降级。
- 缓存复用不再用普通提取结果覆盖完整 SHA。
- 发布仍按完整正文、附件和媒体组合验证，并记录完整模式。
- 即使 HTML 字节不变，只要完整附件/媒体组合变化，状态也会进入 `source_changed`；不修改已发布事实或人工字段。

`tests/test_complete_sync_v1118.py` 新增7个回归用况，覆盖真实调用顺序“发布→普通同步→来源续鲜”：无规则建议的缓存复用、日常完整刷新、仅访问计数变化、旧完整发布记录兼容，以及正文、附件、媒体变化均不续鲜。后3种变化保留原公开目录内容。

128项完整证据/活动核验专项通过，另35项既有审核队列兼容回归通过；日志分别为 `complete-sync-tests.txt` 与 `complete-sync-compatibility-tests.txt`。没有调用 AI，也没有修改生产数据。自动14天复核中的动态原始 HTML 审计由活动子任务另验收，不能用本记录替代其结果。
