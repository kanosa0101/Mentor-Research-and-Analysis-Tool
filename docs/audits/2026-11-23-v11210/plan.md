# v1.12.10 优化计划

基线为已交付的 v1.12.9，最终提交 `d4f6974287b1a6fcaa493975eb03b0c7444db716`。继续纯在线定位，不新增学生业务模块。导师资料由 Sol 子代理分院系核验，主代理负责用户流程、共同规则、集成及发布。

## 一、复现与范围

手机导师详情的五个操作占据三行，先于姓名、方向和联系方式。现有三份实际截图及隔离预览表明，仅调整操作组位置即可让关键信息提前约 178 像素。正式实现仍需验证长字段、照片、宽屏及项目上下文。

西电、川大已有采集入口，但试点发现明确方向漏抽、栏目标题或其他页面信息混入方向。生产自动维护已经更新部分档案，因此所有候选以当次生产原字节为基线，不沿用本地旧缺口作为新增量。

## 二、最小实现与分项验收

- 详情先呈现姓名、导师资格、方向与联系方式，再放原有操作。保留全部现有入口、链接参数、收藏和对比状态，使用真实 DOM 顺序保证键盘访问一致。验证手机、桌面、大字号、长字段、缺邮箱、照片、同院与跨院项目。
- 西电按本人研究栏目和联系栏配对提取，区分教师平台及学院个人页面，保留官方名录的同名多链接问题。川大按名录的精确路径和本人栏目提取，同名人员分别绑定。独立主页和邮箱须有本人证据，普通采集不能绕过字段队列的归属与人工值保护。
- 各代理提交原件、来源 URL、实际时间、哈希、生产原档和候选差异。空白填入与非空纠错分别计数；当前网页为空不能直接撤销原值。
- 实测普通采集、质量队列、字段队列和 CLI 的适用行为，保留同值重新核验能力，并确认重复运行不反复写入或请求。未确认项保存具体原因。
- 西电已复现同一导师旧短入口失效、学院名录另有完整 HTTPS 首页的恢复断点。限定相同主机、相同大小写个人目录、具名名单链接、本人姓名及自链后，允许质量队列迁移到完整首页。人工／已核验 URL 或明确邮箱冲突继续保留原档；其他主机、语言、目录和参数均不适用。

## 三、集成与实际内容核验

独立复核各批数据和解析边界，以正式可重复运行的规则产出候选。逐文件比较生产版本，拒绝覆盖已变化的原档。验证真实新增字段在查找、详情、对比和联系流程可用，保留原件及可回滚备份。导师资料变化与院校活动、政策更新分别统计。

## 四、发布与后验

完成相关回归、完整测试和构建，部署前后校验源码与公开数据。使用真实浏览器验证推荐、登录、申请、材料和沟通；清理专用测试数据。核对 GitHub 主分支、标签、部署版本、原有服务和维护定时器，再交付本版结果。使用的网络路径明确记录，不将代理或浏览器验收误称为直连正常。

## 后续自动维护缺口

本轮复核确认：川大规则可自动补空并复查同源同值，已审定的旧标题污染可在本次清理；但官网把已有研究方向改成另一组真实内容时，目前保留旧值和旧来源日期，不会稳定生成独立的字段变更核验任务。未被现有混合内容规则识别的历史噪音也可能不进入队列。后续应优先利用现有维护和审核流程记录这些差异，区分有效空页、来源失败与实值变化，不增加学生端模块。本次交付不得将这些保留项描述为已自动更新。
