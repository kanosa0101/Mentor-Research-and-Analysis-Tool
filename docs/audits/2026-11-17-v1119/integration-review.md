## 发现与复测

| 等级 | 最小复现 | 独立复测结果 |
| --- | --- | --- |
| P1 导师字段误归属 | 原登记页中并列放置张老师和李老师的栏目，只在李老师栏提供邮箱及个人主页。旧实现将两项写给张老师，且把同页 SHA 标记成本人证据。另以张老师为 `h1`，李老师或英语人员标题为 `h2` 复测。 | 同级、异级、带人员标签的标题，以及 `John Smith`、`Professor John Smith` 用例均保留字段缺口。本人栏内的明确邮箱仍可提取。 |
| P1 AI 复检掩盖真实遗漏 | 原句同时要求副教授签署推荐信、原件密封并骑缝签字。实际材料值只有前半句。第一次模型判为遗漏，描述指明漏了密封签字，但摘录仅引用前半句。旧实现进入复检，并可被第二次一致结论放行。 | 修复后实际值只保留前半句时仍需人工且零次复检。完整保留对应字段官方摘录时允许一次复检，重复处理复用已持久化的同一结果。 |
| P2 限流后丢失接续位置 | 主详情登记联系页，该联系页第一次返回 429。旧实现将联系页从队列移除并标记为已核验，24 小时冷却结束后仍需等待 30 天。 | 修复后先保留待查地址，模拟第 25 小时重新请求该地址并取得邮箱。原详情只请求一次。 |
| P2 外部缓存绕过官方边界 | 为外域登记地址写入一个 SHA 正确且日期、登记地址一致的 legacy 原文缓存，随后运行字段任务。旧实现发起零次 HTTP 请求，把缓存中的外站邮箱写成官方邮箱。 | 独立复测确认既有外域缓存不能用于补字段。主详情缓存和解析器补充读取均应用当前官方来源准入。 |
| P2 中断后原文 SHA 错配 | 首轮把联系页入队，次轮从联系页把邮箱写入档案。模拟该轮最终写字段台账前中断，再运行台账盘点。盘点使用新邮箱的来源 URL，却沿用主详情的 SHA。 | 对来源 URL 改变及 URL 相同但正文与字段值改变分别中断后复测。台账从档案恢复来源与已补状态，无法归属的旧 SHA 和抓取时间均已移除。 |
| 主页写入入口 | 字段任务验证目标是否可达之前，常规教授刷新和导师问题刷新也可直接合并解析器返回的独立主页。将导师主页指向不可达目标再跑正常维护入口可触发。 | 两条常规入口均通过阻止回填的测试。同机构目标须成功取证且有本人身份标识才写入。外域声明作为选填候选保留，邮箱维护可独立完成。 |

两所机构并行、同一机构两个院系串行已用三条档案和线程屏障验证。记录的分机构请求数分别为 2 和 1，同机构并发峰值为 1。重定向逐跳预算、PDF 白名单、主页选填与主缺口分开计数、人工字段保留、活动历史及人工编辑保护均纳入定向套件。

## 已填二级来源邮箱的周期复核

用 `mentor_fields.run` 在临时档案上测试正常调度。已有二级来源邮箱的档案在第 13 天发起零次请求，第 14 天无需清空邮箱即可复核。恢复后按每轮一次请求接续，已通过 SHA 校验的取证可跨轮复用。唯一本人邮箱在同一来源正文变化或官方链接换址后可更新。暂时失败、当前正文取消公开邮箱和角色邮箱均保留档案原值、原日期与上次成功证据，复核状态与字段缺口分别统计。复核取证期间写入的人工邮箱也得到保留。

| 等级 | 最小复现 | 最终独立复测 |
| --- | --- | --- |
| P1 同名档案的邮箱归属 | 建立两条同名但档案 ID 和官方本人详情 URL 各异的记录。一位导师已登记某邮箱，另一位导师的来源也返回该邮箱。初版复核按姓名排除自身所有权，误把两条档案视为同一人。 | 复核保留原邮箱并标记共享归属。分别从主详情合并、站点钩子和官方链接页执行首次补空，三条入口均保留缺口和原所有者的邮箱。 |
| P1 浙大 PDF 换版的同名换人 | 由登记招生栏目读取旧公告及名单 PDF。新年度公告和新版 PDF 仍只有一条同名记录，但所室机构已变且邮箱不同。 | 正常维护入口经两轮取证后保留旧邮箱、原日期和旧 PDF 证据，状态为 `identity_evidence_missing`。同所室对照可更新邮箱，以新版 PDF 的 URL 和 SHA 作为成功证据。 |
| P2 同日同 URL 中断后继承旧 SHA | 已从联系页补入邮箱。同日通过配置变化提前复核，原 URL 返回新正文和新邮箱。档案写入完成后，模拟最终台账写入中断。初版盘点会把上次的 SHA 绑定到新邮箱。 | 恢复后保留已写入的新邮箱，台账按来源、实际核验值及抓取日期校验继承条件，旧 SHA 未重新绑定给新值。 |
| P2 旧 404 链接阻断换源 | 官方本人详情仍同时列出旧 `/a` 和新 `/b`。旧链接先入队并返回 404，新链接有本人标题和唯一的新邮箱。初版复检在旧链接终止，后续轮次也未请求新链接。 | 用一轮两次请求、次轮一次请求复测，请求顺序为主详情、`/a`、`/b`，新邮箱最终按 `/b` 原文写入。限流和服务器暂时错误仍保留旧值并退避。 |
| P2 预算断点的候选原文丢失 | 两次请求预算收取主详情和含候选邮箱的 `/a`，留下 `/b` 待查。删除 `/a` 的缓存正文后启动下一轮，`/b` 无邮箱。初版仍从队列状态采用 `/a` 的候选值。 | 提交前重新核验候选和其上游链接原文，发现证据缺失后进入重试。档案原值和上次成功证据保持原样。 |
