## CI 与站点生成

CI 先安装统一依赖并执行 `pip check`，再准备 Chromium 和系统依赖、生成站点，然后依次运行 Python、Node 和预检。用 Git 的 NUL 分隔路径输出核对，7198 个索引移除路径与生成清单完全一致，41 个站点源码与静态输入继续跟踪。原工作目录中的生成文件全部留存。去除生成物后的独立工作区能够重新构建，预检的导师记录与站点数据均为 7173 条。

发现过一项 P2。原实现带 `--allow-open-issues` 时，缺少问题类型、引用、说明及首次记录日期的条目也能作为已登记问题通过。修复后用临时根复测，合法未关闭问题按告警报告，缺项、畸形 YAML 容器、非布尔状态、坏 JSONL、站点 ID 不一致均返回 1。重建数据的预检为 35 组资料告警、0 项结构问题。

独立浏览器复查覆盖显式空值、学校级、院系级和已有项目四种回跳。只填写导师资格时，政策链接不会生成申请学位或渠道。指向我的申请的显式目标保留原值。[找导师页面验收](ux-polish.md)

## 部署路径与恢复

部署先停维护定时及审核入口，确认运行中的写任务已结束，再绑定公开数据、公开来源配置及展示所需缓存的快照。长构建期间公开 Web 继续运行。阶段准备只使用列入名单的公开输入，复制及构建前后核对公开输入 SHA。若公开缓存输入变化，安装会在停止 Web 前退出。

安装短停 Web 后才计算私人文件保护快照。独立模拟了构建完成后用户保存账号，以及最后一个请求在停止 Web 返回前写完账号。两例均安装成功，原目录和最新账户内容保留，保护快照记录的就是新写入内容。回滚路径只触及本包实际变更的源码和文档、站点目录及本次审计收据。

独立在临时根验证了正常安装、私有工作流文件成员被拒、公开缓存输入漂移时拒绝安装，以及站点已切换后模拟 Web 启动失败。失败后恢复旧站点、旧根文档的原字节、行尾和原有收据状态，原样保留 `data/`、`var/` 以及无关缓存。另验证了只安装最终文档时的成功路径，以及写最终版本指针失败后恢复文档和指针。
