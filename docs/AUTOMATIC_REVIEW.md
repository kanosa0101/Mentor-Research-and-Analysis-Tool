# 自动核验、来源准入与维护提醒

> v1.10 在原有证据流程上增加统一[内容分类门禁](CONTENT_RULES.md)。必须登记实际组织者、机构或个人层级以及当前官方正文中可定位的归类原句；未分类或证据不足的记录不能发布为活动。机构活动进入活动列表与公众提醒，个人招募进入导师资料或待关联记录，正式招生通知另行展示。旧ID和已有申请快照继续保留。

2026-11-17修订至 v1.11.9。服务器定时任务负责发现、抓取、续核、重试和超时提醒。模型根据公开官方证据校对拟发布内容。已有政策的语义变化、未公开条件和无法完整提取的复杂附件仍须核对。2028 届覆盖情况以当期官方公告和已核验数据为准。

## 三种处理结果

| 模式 | 范围与条件 | 写入行为 |
| --- | --- | --- |
| 受限自动发布 | 已启用的可信 HTTPS 官方来源、完整 HTML、可核对的 PDF/DOCX/DOC/XLSX 附件及可核验媒体。院校组织的冬令营、夏令营或科研实践须明确申请对象、材料、报名入口、联系方式及申请窗口 | 规则提取完整栏目，模型逐字段核对，发布门禁再核对来源。全部通过且启用发布模式后写入公开目录 |
| 需人工处理 | 混合学位或批次、身份与届别歧义、扫描件、未核验信息图片、未支持的 XLS/ZIP、未公开要求、实际材料遗漏、已发布事实变化、同范围政策冲突或人工修改 | 保留阻断原因及原证据，供维护者在工作台核对 |
| 仅辅助建议 | 维护者用 `automatic_review.run` 的 `assistant` 参数显式启用。适用于有 SHA 匹配的完整公开 HTML、尚未发布且未进入历史的草稿 | 摘录逐字匹配原文后写入 `ai_suggestions`。人工字段和私有备注保留在本地，建议只供维护台查看 |

无 AI 配置时默认不调用服务。`eligible` 只表示评估通过，尚未发布；`published` 与 `renewed` 才表示该次写入完成。新栏目解析成功、来源 HTTP 200、AI 回答“符合”都不足以单独触发发布。

自动活动新发支持明确邮件申请，或当前官方公告明确链接的同机构 HTTPS 报名系统。只核对公开报名入口及原文步骤，不登录、不替用户提交，也不把系统入口本身当活动。时间须为唯一、完整且未结束的起止日期，或正文明确“长期/全年接受”且属于机构科研招募；不把没有截止当作长期开放，不把月份截止补成月末，不根据活动年份推断毕业届别。申请对象明确肯定、唯一的“2028届本科生”等原句可记录毕业届别；排除、范围、入学年份映射或其他歧义仍阻断。主办单位必须与已登记学校和院系身份一致。具体时点、例外条款及栏目结构无法安全解释时交人工。

## 已核验内容如何续核

已发布条目在最近核验不足 14 天时跳过常规 AI 续核，日常来源监测仍继续。到期或证据恢复后，任务确认公开目录与上次核验字段一致，核对完整正文、链接、附件、媒体的组合证据版本，并在写入前再次回源。访问计数等页面外壳变化只改变原始 HTML SHA 时，组合证据仍一致即可续核，旧、新原始 SHA 与组合版本都保留在记录里。

续核保留原申请事实、人工核验来源及原人工日期，只更新本次证据核验记录。原文或已发布字段变化时转人工，不能把旧的人工批准自动套到新条件；人工编辑与 AI 并发时拒绝旧结果。模型只接收公开官方文本，不接收个人成绩单、材料路径、联系历史或私人项目。

## 发现新的可信栏目

从已维护的机会栏目、政策入口和已登记院系主页出发，只在同机构边界最多展开两级 HTML 链接。每轮有入口数与候选数上限、每个入口默认 6 小时到期，保留父来源、原文摘要、解析示例和检查时间。登录、搜索、结果导航、非公网地址、跨机构跳转、非标准端口和不可解析的 API 外壳不作为自动可用来源；中科院不同研究所不共享准入边界。

新栏目先是候选；生产发布模式允许受限自动准入：再次抓父页确认仍链接该同名栏目，再抓栏目确认内容版本一致且存在可解析的独立活动公告。机构边界、导航类别或版本检查失败均不接入；维护台保留人工准入入口。配置写入前备份原 YAML，重复核准不重复添加。拒绝候选不会删除已接入配置，已接入来源不能用“拒绝候选”假装撤销。

本轮增加57个已登记院系主页种子。隔离试点入口池182项，生产首轮192项；每15分钟最多检查8个入口，理论完整轮转至少6小时。首轮8个候选预算实际只完成1个入口，不能承诺6小时覆盖全部；耗时与预算限制会延长发现周期。这是新栏目发现周期，已接入来源仍按各自1/6/24小时到期时间监测。

## 政策与导师资料的自动维护

`maintain_public.py` 每小时执行政策源检查、政策证据续核、导师轮转、资料问题处理、通知检查及页面重建。政策续核每轮最多20项，导师资料问题最多40项；各阶段独立落盘，某阶段失败不会停止其他阶段。

`policy_revalidation` 绑定政策字段摘要、全部官方来源/附件版本及原句。完整证据仍一致时自动确认，保留原人工日期并另外显示系统复检时间；通常14天后续检。新条件、缺失原句、附件变化转待复核；网络失败按2至48小时退避，需人工处理的内容24小时后再检查来源变化。配置或政策变更立即重新排队。

`mentor_quality` 把原67条问题和后续抓取失败纳入持久队列，依据官方名册与个人页处理失效链接、身份、职称、共享邮箱及数量异常。姓名相同不足以合并，须身份或公开邮箱等证据对应；模板共用邮箱从导师个人联系方式撤回。已解决项保留证据，每7天复检；未解决或读取失败的质量问题每24小时重查。常规导师轮转中的人工阻塞在解析器/来源配置变化时立即重开，否则7天重试；其网络错误使用独立退避。不用自动填猜测值消除问题数量。

v1.11.9 的字段专项每小时最多48人、96次请求，4个机构并行、同机构串行且最多8次请求。未完成的名册、本人页及其联系页保留接续位置，限流与临时失败不当成已查完。独立主页是补充字段，不算主缺口；新主页仅在同机构目标可达且身份对应后写入，外域声明保留候选。

已经填上的自动二级来源邮箱通常14天复检，配置或已知来源版本变化可提前唤醒。浙大钩子从稳定官方招生栏目查找新版公告和导师PDF，邮箱变更需与旧附件的本人身份依据对应。字段值、来源URL、原文SHA和成功时间共同绑定；重启或缓存损坏不能给新值套用旧SHA。无法确认时保留旧值及旧成功日期，并记录原因、重试与维护告警；人工邮箱保持优先。实际批量与复检证据见[导师维护审计](audits/2026-11-17-v1119/contact-engine.md)。

`quality_status` 汇总政策续核、导师资料和新政策入库三类问题的原因、官方链接、下次重试和24小时维护时限，送入既有维护通知。首次排队时间不因重试重置；状态文件缺失或任务异常不能显示为全部健康。通知只面向维护者，学生页面只显示经核验的事实与适用年度。

新域名/机构需人工登记可信入口；特殊 API 或非 HTML 需要独立解析配置。接入栏目只让后续监测发现公告，**不会发布其中任何机会**。历史夏令营栏目也可以成为监测来源，但其中历史公告不能计为当前报名。

## 新政策与附件的自动入库

`policy_intake` 每小时从已登记的官方通知和机会栏目处理正式招生公告，每轮最多 2 条。完整官方日期显示临近截止的候选优先，其次是标题明确的当前或后续招生年度。年度、学位、渠道、院系身份、完整条件、材料、流程、联系方式和各步骤截止均须通过规则检查。网报与材料送达截止分别保存。已有相同 URL 或相同招生范围的政策保留原记录。

HTML 和链接的 PDF/DOCX/DOC/XLSX 附件共同形成完整核验输入和组合版本。正文明确将材料要求指向附件时，唯一的官方材料栏目可补入拟发布材料字段，并保留出处。PDF 绘制表格保留单元格、行列跨度及完整非空白字符。扫描、未核验图片与无法解析的混排保留阻断原因。模型核对全部实际展示字段，服务器记录原句和哈希，发布前再次核对正文、附件和已登记入口。预评估通过后，定时发布任务可复用同版本、同全文及同提案的结论。

新政策状态位于 `cache/policy_intake/state.json`，原始证据在 `cache/policy_intake/evidence/`。已结束的历史政策保留证据并7天复查，不计维护待办。待处理记录有原因、下次动作、首次等待时间和24小时维护时限，在既有维护台资料问题区展示；不将未通过的提议内容提供给学生。已发布政策使用 `review_method: automatic_evidence`，页面标为“自动证据核验”，不冒充人工核对日期。

导师目录另有每小时最多2个院系、共16次HTTP请求的持续轮转，进度独立于单条问题退避。官方名册的新差异只进入候选台账，不自动增加导师；姓名链接、个人页身份和本人邮箱一致后才修复原条目。研究方向与招生资格依明确本人原句提取，否定、历史资格和身份不清保持空缺。

## 运行、预算与重试

活动任务每 15 分钟唤醒，每轮通常处理 2 条活跃候选。活动核验、新政策核验、明确启用的辅助摘录和有证据的复核共用每日 10 次调用额度，按 UTC 日期计算。已发送的失败请求计入额度。到日上限后等待次日 UTC 00:05 后的处理轮次。

网络或服务暂时失败采用 2、4、8、16、24 小时退避。可信栏目、正文、附件或完整证据状态发生变化时，定时任务重新检查受影响条目。规则升级只重新处理与变更相关的旧人工阻断。若模型报告遗漏，只有实际发布值逐字包含该字段绑定的整段官方摘录，才算有反证。全部被标记字段满足这一条件时，任务携带反证复核一次。复核绑定规则版本、完整原文和提案。共享额度等待或 HTTP 402 无判决时，保留原判决并等待恢复后复核。其他失败保留已经开始的复核记录。实际漏项、歧义和冲突保留原阻断。

服务按稳定错误码归类。连接、读取和总时限错误、408/425/429/5xx 与可重试协议截断进入有界退避。TLS、认证和其他不可重试错误进入人工排障。调用共用受限 SSE 传输，45 秒读取空闲与 120 秒总时限。有效结论需要完整结束标记、有效 JSON 和可定位原句。仅对已实测的 50X 主机及模型关闭额外推理。传输层每次申领只发一个请求，日志只保留耗时、字节数、阶段及错误码。

HTTP 402 单列为 AI 服务不可用。活动和新政策保留已有原文、组合版本与判决，等待对应服务配置冷却，首次 6 小时，再次 12 小时，之后最多 24 小时。冷却结束由下一条已通过前置门禁的真实待核验任务申领一次试探，同配置并发任务等待，进程中断时申领会过期。若遇超时等情况而尚不能确认恢复，再等待 15 分钟，402 的退避级别延续。传输成功后恢复处理。更换地址、模型或凭据可使用新配置，仍沿用当日共享额度。冷却跨 UTC 午夜保留，等待不计调用，发出的请求计入当日额度。任务无须另外发付费探测。没有有效核验结论时，发布门禁继续阻止写入。

下列命令仅供维护者在已配置依赖与私有凭据的服务器或开发环境中，从项目根目录运行。学生只访问在线网站，不下载运行包、不执行维护脚本；部署和权限边界见[维护交接](../HANDOVER.md)。

```powershell
# 只评估：可能调用已配置的 AI，但不发布、不发维护推送、不重建公开页面
python scripts/run_review_pipeline.py --limit 2 --discover

# 显式启用受限发布、维护推送和目录变更后的在线页面更新
python scripts/run_review_pipeline.py --publish --discover --limit 2 --max-seeds 8 --max-candidates 8

# 单独处理队列；不带 --publish 只评估，不承担页面重建
python scripts/process_reviews.py --limit 2

# 仅发现新栏目候选，不接入、不发布
python scripts/discover_sources.py --max-seeds 4 --max-candidates 8
```

编排分阶段执行来源发现、自动处理、审核告警、维护推送、在线页面重建（`public_pages`）及指标。一个阶段失败会保存 `partial` 与阶段名，其余独立阶段继续。告警刷新失败时不发送旧维护通知；只有公开目录摘要变化且启用发布模式才重建，成功后推进已构建摘要，失败下轮重试。维护不再生成客户端资料ZIP，旧公共资料下载及更新接口关闭。生成文件逐文件替换，不承诺中途 I/O 失败时整站整体回滚。服务错误不回显供应商响应或凭据。

## 审核优先级与超时

v1.11.5 来源轮转按入口分配候选预算，已登记候选不重复消耗同轮额度；优先招生与营活动栏目。仅在 `--publish --discover` 下执行替代来源恢复：每轮最多1条异常公告、16次HTTP请求（重定向也计数），按院校/院系登记的可信栏目寻找精确同名公告。只有旧正文哈希有效、新旧完整内容一致、父栏目已经入监测、没有人工或已发布字段、没有待核验图片附件，且第二次回源仍一致时，才接续空白草稿。接续不发布事实；人工字段、正文变化和缺旧证据留候选。旧来源的迁移链阻止同名旧候选重新建档，原地址后来出现不同公告仍可发现。

疑似栏目不作为可报名活动；只有当前有效来源错误计入修复积压。恢复状态与证据链保存在 `cache/opportunity-recovery.json`，原始失败记录保留。404、访问限制等导师错误转入官方目录发现，共用院系缓存；临时故障退避，解析不支持与身份冲突单独分流。修复详情见本版审计，不能把“分类完成”写成“资料已补齐”。

| 优先级 | 典型条件 | 审核 SLA |
| --- | --- | --- |
| 紧急 | SHA 匹配的官方正文明确截止在 3 天内 | 2 小时 |
| 高 | 官方截止在 14 天内、明确当前准备届别、已核对当前轮次、来源变化/不可读或核验过期 | 12 小时 |
| 普通 | 新机会或适用轮次仍待确定 | 24 小时 |
| 低 | 正文明确报名截止已过，等待历史分流 | 72 小时 |
| 已处理 | 已发布或按有效证据归入历史/非报名 | 不占用审核 SLA |

SLA 是维护处理目标，不是给申请人的报名时间保证。截止必须能在当前 SHA 匹配的官方正文中确定，AI 单独给出的日期不增加紧急优先级；活动年份不当作毕业届别。

首次排队时钟持久化，重复抓取、重复运行和 AI 尝试次数不会重置等待时间。官方版本或来源状态变化、已解决条目重新进入队列时重开时钟，保留 `overdue`、`reopened`、`resolved` 事件；同一轮次超时只记录一次。移出队列的记录也会标记解决。

## 维护通知和访问边界

维护者可自愿开启后台浏览器审核超时通知，需浏览器授权并有已配置的 VAPID 推送服务；没有订阅就不发送；存在超时任务而无维护者订阅时，维护台明确提示当前未投递后台提醒。订阅凭据只存散列，维护订阅和投递记录在 `var/review-notifications/`，与申请用户的 `var/push/alerts.sqlite` 独立。重试最多 5 次；过期端点删除，失败和耗尽可在工作台查看。正常运行按超时轮次去重；发送成功后进程恰好中断而未落记录时仍可能重复，不能承诺严格一次到达。

维护工作台打开时的浏览器通知是另一种选择，关闭页面即不继续页面轮询。后台推送依赖服务、浏览器和系统，发送服务接受不等于终端已展示。两种维护提醒都不会推送给普通申请用户，也不是个人项目截止提醒。

维护台固定在 `127.0.0.1:18769`，带 Host/Origin 与写请求令牌检查。公网 `review.html`、`review.js`、`review-worker.js` 及审核 API 返回 404。远程维护使用已有授权 SSH 账号转发，例如：

```text
ssh -N -L 18769:127.0.0.1:18769 <维护账号>@8.213.137.82
```

在自己的浏览器打开 `http://127.0.0.1:18769/review.html`。不要开放服务器的 18769 入站端口或给公网服务增加审核写路由。

AI 服务配置只由维护者置于服务器私有目录，限制文件权限。生产 unit 使用 `LoadCredential=ai-config:...`，经 `MENTOR_AI_CONFIG_FILE` 读取；工作台不需要该凭据。配置含 `enabled`、`api_key`、`base_url`、`model`、`daily_limit`，文档、公开页面和源码发布物不附任何真实 key。默认兼容地址与模型在代码配置中；更换服务时先验证 API 和证据格式，不复制用户密钥到页面、源码或命令日志。

## 排障证据与交付边界

v1.11.8 的真实误判修复以业务值为核对对象，删除发送给模型的重复整段摘录，不删除官方全文、真实限制或本地原句门禁。新政策发布前校验展示值与提议检查项一一对应；材料条目删限制、时间改一天均会被拒绝。全局要求与只适用某种学历的语言条件按其原文范围分别判断，不用外部常识替换学校标准。三条完整新政策已通过真实AI及发布前回源；模型仍出现过额外误报和服务超时，不能声称消除了所有误判。

读取空闲时限现为45秒，流处理75秒加最后最多45秒读取，总时限仍为120秒，不增加内部重试或改变正常每日10次预算。本轮共16次真实验收请求（政策14次、活动2次），使用共享账本和临时绝对上限25，账本从5增至21；失败也计费计数。发布重放严格复用原来源、完整文本和字段哈希一致的成功结果，未再调用AI。临时验收配置在完成后删除，具体回执以本版交付记录为准。

机构冬季培训班沿用院校活动模型，主办身份须由已登记机构及正文共同证明，报名时间“即日起”仅在明确官网发布日期下解析；活动年不填入毕业届别。DOCX材料按原附件名称分组，保留字数、原创性、签名与日期要求。官方报名段直接指向的腾讯问卷链接可验证HTTPS可达，不能据HTTP200宣称后台表单仍收件或已读取全部隐藏条件。

完整媒体核验只支持有边界的情形：正文明确二维码与相邻报名URL一一对应、实际解码一致且二维码外无文字；人工已看过的往届图片/附件校徽以来源URL和SHA绑定复用。未知图片、改变后的图片、未批准的文档媒体仍需处理。普通同步保存 `evidence_mode: complete`，附件和图片变化也会触发待复核；发布与续核再次获取完整组合版本，不能只比较HTML。`sites/evidence_media.yaml`是维护证据，不提供学生编辑入口。附件遍历按URL排序，保证不同进程形成同样的全文和核验输入。

v1.11.7 将正文已获取但附件/图片证据未闭合的任务标为 `needs_evidence_review`，不送往失效URL恢复；无独立活动链接的来源标为 `not_column`，默认7天复看，父证据变化可提前唤醒。旧图片公告只有日期/标题时仅降低优先级，保持未核验。新政策发现即进入台账和等待统计；导师首次纳入的字段库存先排队，真正检查后仍有解析/身份问题才开始处理SLA，官网未见明确字段30天复看。DOC/XLSX纳入完整证据，不能据此忽略宏、图片或格式歧义。真实AI仍可能误报，应保留完整提案与拒绝原因，不通过重抽或修改事实强行获得发布。
