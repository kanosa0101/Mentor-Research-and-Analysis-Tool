# 自动核验、来源准入与维护提醒

> v1.10 在原有证据流程上增加统一[内容分类门禁](CONTENT_RULES.md)。必须登记实际组织者、机构或个人层级以及当前官方正文中可定位的归类原句；未分类或证据不足的记录不能发布为活动。机构活动进入活动列表与公众提醒，个人招募进入导师资料或待关联记录，正式招生通知另行展示。旧ID和已有申请快照继续保留。

2026-11-16修订至v1.11.4。日常发现、抓取、原文一致续核、问题重试及超时提醒由服务器定时任务执行，不需要聊天代理在线。AI只辅助核对公开证据，不代替官方来源。实际部署与验收见[v1.11.4交付记录](../deploy/DELIVERY_V1.11.4_2026-11-16.md)。新政策的语义变化和复杂附件仍须审核，不能把自动化启用等同于2028届资料已经齐全。

## 三种处理结果

| 模式 | 范围与条件 | 写入行为 |
| --- | --- | --- |
| 受限自动发布 | 已启用的可信 HTTPS 官方来源；完整可核对 HTML；本科冬令营、夏令营或科研实践/实习类活动；对象、材料、邮件申请方式、联系邮箱与唯一报名窗口都有完整栏目；无多批次、附件、人工改动或身份歧义 | 规则提取完整栏目，AI 逐字段交叉检查，再通过原有发布门禁重新回源；全部通过且显式启用发布模式才写公开目录 |
| 需人工处理 | 正式推免或学位招生、入学年份与毕业届别映射、届别否定/范围歧义、混合学位/身份、多批次、图片或 PDF/DOCX 等附件、系统报名、材料遗漏、来源变化、既有人工编辑、模型提示冲突或语义校验失败 | 保留阻断原因及原证据，不自动覆盖人工事实；维护者在工作台核对并明确发布 |
| 仅辅助建议 | 未发布且非历史的草稿，包括已有人工字段的草稿，有已存档且 SHA 匹配的完整公开 HTML，适合摘录条件、材料、申请方式或联系人 | 仅写 `ai_suggestions`，逐字匹配原文并只读展示；保留所有人工字段和私有备注，不向 AI 发送备注，并拒绝并发编辑后的旧结果；不核验附件、届别或本人资格，不改变可发布结论 |

无 AI 配置时默认不调用服务。`eligible` 只表示评估通过，尚未发布；`published` 与 `renewed` 才表示该次写入完成。新栏目解析成功、来源 HTTP 200、AI 回答“符合”都不足以单独触发发布。

自动新发目前只支持明确邮件申请。时间须为唯一、完整且未结束的起止日期，或正文明确“长期/全年接受”且属于机构科研招募；不把没有截止当作长期开放，不把月份截止补成月末，不根据活动年份推断毕业届别。申请对象明确肯定、唯一的“2028届本科生”等原句可记录毕业届别；排除、范围、入学年份映射或其他歧义仍阻断。主办单位必须与已登记学校和院系身份一致。具体时点、例外条款及栏目结构无法安全解释时交人工。

## 已核验内容如何续核

已发布条目在最近核验不足 14 天时跳过 AI 续核，日常来源监测仍继续。达到 14 天后，只有原始 SHA、正文版本、现有公开目录与原记录一致，且关键字段仍有完整同页证据、无附件或人工修改等阻断，才可重新交叉检查并续核。

续核保留原申请事实、人工核验来源及原人工日期，只更新本次证据核验记录。原文或已发布字段变化时转人工，不能把旧的人工批准自动套到新条件；人工编辑与 AI 并发时拒绝旧结果。模型只接收公开官方文本，不接收个人成绩单、材料路径、联系历史或私人项目。

## 发现新的可信栏目

从已维护的机会栏目、政策入口和已登记院系主页出发，只在同机构边界最多展开两级 HTML 链接。每轮有入口数与候选数上限、每个入口默认 6 小时到期，保留父来源、原文摘要、解析示例和检查时间。登录、搜索、结果导航、非公网地址、跨机构跳转、非标准端口和不可解析的 API 外壳不作为自动可用来源；中科院不同研究所不共享准入边界。

新栏目先是候选；生产发布模式允许受限自动准入：再次抓父页确认仍链接该同名栏目，再抓栏目确认内容版本一致且存在可解析的独立活动公告。机构边界、导航类别或版本检查失败均不接入；维护台保留人工准入入口。配置写入前备份原 YAML，重复核准不重复添加。拒绝候选不会删除已接入配置，已接入来源不能用“拒绝候选”假装撤销。

本轮增加57个已登记院系主页种子。入口池快照182项，每15分钟最多检查8个入口，理论完整轮转约5.7小时；实际受超时和候选预算影响会更长。这是新栏目发现周期，已接入来源仍按各自1/6/24小时到期时间监测。

## 政策与导师资料的自动维护

`maintain_public.py` 每小时执行政策源检查、政策证据续核、导师轮转、资料问题处理、通知检查及页面重建。政策续核每轮最多20项，导师资料问题最多40项；各阶段独立落盘，某阶段失败不会停止其他阶段。

`policy_revalidation` 绑定政策字段摘要、全部官方来源/附件版本及原句。完整证据仍一致时自动确认，保留原人工日期并另外显示系统复检时间；通常14天后续检。新条件、缺失原句、附件变化转待复核；网络失败按2至48小时退避，需人工处理的内容24小时后再检查来源变化。配置或政策变更立即重新排队。

`mentor_quality` 把原67条问题和后续抓取失败纳入持久队列，依据官方名册与个人页处理失效链接、身份、职称、共享邮箱及数量异常。姓名相同不足以合并，须身份或公开邮箱等证据对应；模板共用邮箱从导师个人联系方式撤回。已解决项保留证据，每7天复检；未解决或读取失败的质量问题每24小时重查。常规导师轮转中的人工阻塞在解析器/来源配置变化时立即重开，否则7天重试；其网络错误使用独立退避。不用自动填猜测值消除问题数量。

`quality_status` 汇总两类问题的原因、官方链接、下次重试和24小时维护时限，送入既有维护通知。首次排队时间不因重试重置；状态文件缺失或任务异常不能显示为全部健康。通知只面向维护者，学生页面只显示经核验的事实与适用年度。

新域名/机构需人工登记可信入口；特殊 API 或非 HTML 需要独立解析配置。接入栏目只让后续监测发现公告，**不会发布其中任何机会**。历史夏令营栏目也可以成为监测来源，但其中历史公告不能计为当前报名。

## 运行、预算与重试

生产编排约定每 15 分钟唤醒，每轮最多 2 次 AI 请求，默认生产日额度 10 次，按 UTC 日期重置。自动核验与仅辅助摘录共用日预算；失败请求也计入预算。到日上限后等待次日 UTC 00:05 后的处理轮次，不能通过重启绕过额度。

网络或服务暂时失败采用 2、4、8、16、24 小时退避，上限 24 小时；同一版本已明确需人工处理的条目不会不断重试烧预算。辅助摘录失败与自动发布失败分别记录，无法自动完成的任务仍在人工队列中。此退避是 AI 处理规则，和机会来源监测的 1/6/24 小时及来源错误最长 48 小时退避不是同一机制。

下列命令仅供维护者在已配置依赖与私有凭据的服务器或开发环境中，从项目根目录运行。学生只访问在线网站，不下载运行包、不执行维护脚本；部署和权限边界见[维护交接](../HANDOVER.md)。

```powershell
# 只评估：可能调用已配置的 AI，但不发布、不发维护推送、不重建公开页面
python scripts/run_review_pipeline.py --limit 2 --discover

# 显式启用受限发布、维护推送和目录变更后的在线页面更新
python scripts/run_review_pipeline.py --publish --discover --limit 2 --max-seeds 8 --max-candidates 8

# 单独处理队列；不带 --publish 只评估，不承担页面重建
python scripts/process_reviews.py --limit 2

# 仅发现新栏目候选，不接入、不发布
python scripts/discover_sources.py --max-seeds 4 --max-candidates 8
```

编排分阶段执行来源发现、自动处理、审核告警、维护推送、在线页面重建（`public_pages`）及指标。一个阶段失败会保存 `partial` 与阶段名，其余独立阶段继续。告警刷新失败时不发送旧维护通知；只有公开目录摘要变化且启用发布模式才重建，成功后推进已构建摘要，失败下轮重试。维护不再生成客户端资料ZIP，旧公共资料下载及更新接口关闭。生成文件逐文件替换，不承诺中途 I/O 失败时整站整体回滚。服务错误不回显供应商响应或凭据。

## 审核优先级与超时

| 优先级 | 典型条件 | 审核 SLA |
| --- | --- | --- |
| 紧急 | SHA 匹配的官方正文明确截止在 3 天内 | 2 小时 |
| 高 | 官方截止在 14 天内、明确当前准备届别、已核对当前轮次、来源变化/不可读或核验过期 | 12 小时 |
| 普通 | 新机会或适用轮次仍待确定 | 24 小时 |
| 低 | 正文明确报名截止已过，等待历史分流 | 72 小时 |
| 已处理 | 已发布或按有效证据归入历史/非报名 | 不占用审核 SLA |

SLA 是维护处理目标，不是给申请人的报名时间保证。截止必须能在当前 SHA 匹配的官方正文中确定，AI 单独给出的日期不增加紧急优先级；活动年份不当作毕业届别。

首次排队时钟持久化，重复抓取、重复运行和 AI 尝试次数不会重置等待时间。官方版本或来源状态变化、已解决条目重新进入队列时重开时钟，保留 `overdue`、`reopened`、`resolved` 事件；同一轮次超时只记录一次。移出队列的记录也会标记解决。

## 维护通知和访问边界

维护者可自愿开启后台浏览器审核超时通知，需浏览器授权并有已配置的 VAPID 推送服务；没有订阅就不发送。订阅凭据只存散列，维护订阅和投递记录在 `var/review-notifications/`，与申请用户的 `var/push/alerts.sqlite` 独立。重试最多 5 次；过期端点删除，失败和耗尽可在工作台查看。正常运行按超时轮次去重；发送成功后进程恰好中断而未落记录时仍可能重复，不能承诺严格一次到达。

维护工作台打开时的浏览器通知是另一种选择，关闭页面即不继续页面轮询。后台推送依赖服务、浏览器和系统，发送服务接受不等于终端已展示。两种维护提醒都不会推送给普通申请用户，也不是个人项目截止提醒。

维护台固定在 `127.0.0.1:18769`，带 Host/Origin 与写请求令牌检查。公网 `review.html`、`review.js`、`review-worker.js` 及审核 API 返回 404。远程维护使用已有授权 SSH 账号转发，例如：

```text
ssh -N -L 18769:127.0.0.1:18769 <维护账号>@8.213.137.82
```

在自己的浏览器打开 `http://127.0.0.1:18769/review.html`。不要开放服务器的 18769 入站端口或给公网服务增加审核写路由。

AI 服务配置只由维护者置于服务器私有目录，限制文件权限。生产 unit 使用 `LoadCredential=ai-config:...`，经 `MENTOR_AI_CONFIG_FILE` 读取；工作台不需要该凭据。配置含 `enabled`、`api_key`、`base_url`、`model`、`daily_limit`，文档、公开页面和源码发布物不附任何真实 key。默认兼容地址与模型在代码配置中；更换服务时先验证 API 和证据格式，不复制用户密钥到页面、源码或命令日志。

## 排障证据与交付边界

- `cache/review-pipeline.json`：各阶段完成、失败与最近成功构建摘要。
- `cache/opportunity_review.json`：自动状态、阻断原因、原文版本及下次尝试时间。
- `cache/source-discovery.json`：来源候选、父证据与检查轮转；备份位于 `cache/source-discovery-backups/`。
- `cache/review-alerts.json`：维护队列时钟、当前超时及去重事件。
- `cache/policy_revalidation/`、`cache/mentor_quality/`：持久任务状态、证据与最近一轮处理结果。
- `cache/quality-alerts.json`：政策与导师问题的维护优先级、超时和状态可用性。
- `cache/ai-evidence-usage.json`：共用 UTC 日额度；`var/review-notifications/last-delivery.json`：维护推送聚合结果。

上述缓存、私有配置、订阅端点与凭据不进入公开网页、API响应或源码发布物；账号及上传材料也不属于公共构建输入。不再制作学生运行包。来源覆盖、当前报名数量、正式届别和全量导师/政策新鲜度仍须分别看数据快照与官方原文；自动流程启用不能当作这些内容已经补齐的证明。
